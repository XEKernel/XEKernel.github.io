1.5.5 主菜单背景跟随真实时间（2026-11-19 已实现）

用户：「开始页面的背景可以根据实时时间调节阳光位置，比如现在是晚上，
那么打开游戏时就是晚上的城市。」
项规则
时间源Time.get_time_dict_from_system()（本地时间）
太阳方位6 点东升 / 12 点最高 / 18 点西落，高度角按 sin 曲线
⚠ 高度封顶56°。正午垂直光会把画面照平、失去明暗，斜射才有"城市感"
天色10 个关键帧插值（夜 / 黎明 / 上午 / 正午 / 下午 / 黄昏 / 入夜）
夜间楼窗按窗格随机点亮（约 32 % 灯率），亮窗在实例色 alpha 里做标记
测试--hour=21.5 覆盖当前时间（截图与宣传片用，见 §七·五）

⚠ 三条实测教训（都会让画面变丑，记下来）：

#坑正确做法
1实例颜色是按 linear 传进自定义 shader 的调色板要 .srgb_to_linear()，否则整体发白、屋顶过曝
2不开阴影时，垂直面只收到天光 → 楼群一片蓝必须开 DirectionalLight3D.shadow_enabled
3曝光白点要随时间变（白天 1.15 / 夜里 2.0）固定 2.0 会让白天发闷，固定 1.15 会让夜景刺眼

⚠ 面板"实度"要跟着环境调：夜里楼窗极亮、白天背景极亮， 玻璃面板必须能压暗背景（shader 里 bg_dim），否则按钮文字会被背景吃掉。 主菜单用 0.62，设置页用 1.0（几乎不透明）——小字多的页面不能透。

二、视觉基准：先有靶子，再谈建模

⚠ 当前最大的缺口是"没有靶子"：docs/reference/ 只有 CS1 规格，没有一张中国城市的图。 建模 Agent 如果没有参考，产出的必然是"想象中的中国"，而不是真实的中国。

2.1 采集清单（去现场时按这个拍）

组拍什么为什么
村庄独院农房（正面/侧面/俯视）、院墙与大门、村道、柴房/猪圈/晒场、水塘、祠堂开局第一屏就是这个，做不像就全盘错
镇沿街 3–5 层自建房、卷帘门商铺、招牌、菜市场、乡镇政府院镇是"村到市"的中间态，最有辨识度
县6 层砖混住宅排、老单位大院、县城主干道、汽车站对应 R4 的县城限高规范
市（老城）90 年代板楼阵列、窄巷、临街底商、骑楼/雨棚老城肌理 = 低标准规范 + 不规则地块
市（新区）30 层塔楼群、超大街区围墙、大门与门禁、地下车库入口、商业综合体新区肌理 = 高标准规范 + 超大街区
通用元素塔吊、店招、行道树、路灯、公交站牌、围墙、变电箱、晾衣杆、空调外机"一眼中国"靠的是这些小东西，不是主楼

2.2 采集纪律

  • 只作参考，不入库：照片不进游戏、不做贴图（避版权与隐私）
  • 每张照片记 地点 / 年代 / 类型 / 拍摄日期，存 docs/reference/visual-targets/
  • 建筑正面至少 1 张正视、1 张 45°，便于估比例

三、资产管线：建模 Agent 交接契约

这一节是给建模 Agent 的「派活模板」，与 docs/agents.md §三 同级使用。
少了任何一条，产出的模型就进不了图集、合不了批。
📌 提示词怎么写、怎么保证不重样 → 见 14-model-prompts.md（2026-11-23 新建）。
本篇管"交什么规格"，14 篇管"怎么描述出来"。
⚠ 现有 46 个 AI 模型（2026-11-23 实测）暂时一个都不能直接进游戏：
一半没贴图；工业那批 22–26 MB（内嵌 32–39 张图，面数才 1.6–4.8 万）；
住宅那批 7–15 MB 且多为片区级（一个 glb 装整个小区，无法实例化）。
详见 14-model-prompts.md §一 —— 能用的是"参考"和"配色"，不是资产本身。

3.1 输入（你给建模 Agent 什么）

1. 参考图：docs/reference/visual-targets/<类型>/*.jpg（3–8 张，含正视图）
2. 目标 archetype：见 §五 谱系表，必须指定代号
3. 尺寸约束：占地面积、层数、层高（由 R4 的规范年代决定）
4. 三角面预算：见 §3.3
5. 输出路径：assets/models/buildings/<archetype>/

3.2 输出规格（硬性，不满足直接退回）

项要求
格式glTF 2.0 / .glb（Godot 原生支持，不引入 FBX 转换链）
单位米，1 unit = 1 m
坐标系Godot 约定：+Y 向上，正面朝 −Z
轴心点建筑底面中心（便于贴地，不用逐模型算偏移）
朝向正面沿 −Z；行列式板楼长边沿 X
变换导出前 apply all transforms，缩放必须为 1
材质每个模型最多 1 个材质，且贴图必须来自共享图集（§3.4）
命名bld_&lt;era&gt;_&lt;type&gt;_&lt;variant&gt;.glb，如 bld_90s_slab_a.glb
授权同目录附 SOURCE.md：自制 / 参考图出处 / 日期

3.4 图集规则（B3 就要定，不然 B5 必爆）

项规则
图集数量≤ 2 张 4096²（建筑 / 车辆路面各一）
单模型 UV必须落在图集内的矩形区，禁止跨图集
材质数全项目目标 ≤ 8 种
新增资产先看图集有没有空位；没有就替换同类，不许新增图集

⚠ 26 个 archetype 各一张 2048² 贴图 ≈ 400 MB 显存。 图集不是优化手段，是硬约束——它同时决定了能不能合批（11-scale.md §10.4）。

3.5 入库前的五条检查

  1. 三角面在预算内，且 LOD0–LOD3 四档齐全
  2. 轴心在底面中心、缩放为 1、正面朝 −Z
  3. 材质 1 个、UV 在本项目图集内
  4. 同目录有 SOURCE.md
  5. 在 probe_structure.gd 里能被 archetype 正确归类（归错类就不能合批）

四、视觉规范（已拍板部分）

项值来源
直角 / 圆角直角为主，圆角仅限头像、toggle、搜索框、搜索按钮用户长期偏好

4.0 ⭐ UI 材质：磨砂玻璃（2026-11-18 用户明确）

用户：「我喜欢磨砂玻璃的那种模糊效果。」

这可能是"配色待定"的解药。

之前一直卡在"选什么主色"——因为任何高饱和纯色块压在城市画面上都会难看清。 磨砂玻璃的深色半透明 + 背景模糊，天然不抢画面，而且现代感强。

方案效果问题
纯色面板（#1a1f27 不透明）干净挡死 3D 画面，像贴纸
磨砂玻璃（半透明 + 背景模糊）⭐ 像一层玻璃浮在城市上有渲染成本
全透明（只有文字）最不挡可读性差

4.0.1 参数（初始值）

项值说明
面板底色rgba(18, 22, 28, 0.62)深墨 + 62 % 不透明度
背景模糊半径12–16 px太小看不出，太大像糊了
边缘高光1 px 内侧亮线（rgba(255,255,255,0.08)）⭐ 这一条决定"像不像玻璃"
转角直角（与 §四 一致，圆角只给 toggle/搜索框）—
边框1 px rgba(255,255,255,0.12)极淡，不要明显描边

⚠ "1 px 内侧亮线"是最容易被忽略、但最出效果的一条： 真实玻璃的边缘会折射出一点光，没有这条线就只是一块半透明色块。

4.0.2 ⚠ 渲染成本（这个必须提前知道）

Godot 4 没有内置 backdrop blur，要自己做：

做法代价
BackBufferCopy + 自定义 shader 采样 SCREEN_TEXTURE每帧全屏采样，1080p 下 ≈ 1–2 ms
两级降采样再模糊（降采样到 1/4 再升回来）≈ 0.4 ms，质量略降但可接受

⚠ 推荐两级降采样：磨砂玻璃本来就看不清细节，不需要全分辨率模糊。 ⚠ Mobile / Compatibility 后端支持有限，需要在设置里降级为纯色面板（§1.4 的"画质档"）。

4.0.3 哪里用磨砂玻璃（不要到处都是）

用不用
✅ 右侧信息面板❌ 小型 tooltip（成本不值）
✅ 顶部状态栏❌ 热力图图例（要清晰读数）
✅ 模态对话框（设置/存档/关于）❌ 大量列表项（每项一个 blur 会爆）
✅ 主菜单按钮区❌ 3D 世界内的标注

⚠ 原则：大面积、少量、静态的元素用磨砂；小面积、大量、动态的元素用纯色。 每个 UI 元素都套一层 blur，帧率直接腰斩。

4.1 配色方向（提案，待定稿）

⚠ 不是"选一个好看的主色"，而是"让界面不抢城市的戏"。 城建游戏的 UI 每天都压在 3D 画面上，任何高饱和主色都会疲劳。

原则说明
低饱和主色饱和度建议 < 45 %，用在中性灰底上
不做品牌色统治主色只出现在选中态 / 关键数字 / 主按钮，不要到处刷
深色为默认城市夜景与灯光是卖点，深色底更能衬托
让位给画面UI 的对比度来自明度差，不是色相差
数据色单独一套热力图/图表用色阶（红-黄-绿等），与 UI 主色分离

⚠ 热力图配色要遵守中国习惯：涨/高 = 红，跌/低 = 绿（regional_conventions）。 不要用国外的红跌绿涨。

⚠ 具体色值等美术方向定了一起定，现在不锁。 先锁"原则"，不锁"色号" —— 色号过早定死，后面一定返工。

4.2 ⭐ 交互反馈：悬停与点击都必须有回应（2026-11-18 用户明确）

用户：「按钮等鼠标悬停以及点击都要有反馈。」

这不是"锦上添花"，这是"这个软件是不是活的"的判据。 一个没有 hover 反馈的按钮，玩家会怀疑"能不能点"。

4.2.1 三态，每态都要有明显变化

态变化时长
常态底 rgba(255,255,255,0.06)—

7.1 五条总线（各自独立音量，缺一条都不行）

总线内容默认音量可关

7.2 环境音：这一层最值得投入，而且我们有别人没有的优势

环境音是城建游戏"活着"的主要来源，比 BGM 重要得多。

层内容驱动变量

⭐ 素材来源：自己录（这是低成本高回报的差异点）

来源评价
freesound.org（CC0/CC-BY）✅ 通用声（雨、风、车流）够用

7.3 BGM：少、可关、随城市规模变化

「我没有音乐创作的经验，但是像城市模拟这种纯音乐即可。」
项方案
数量2–3 首循环，不做多（玩家会关掉）
来源免版权库（Kevin MacLeod / Pixabay / FMA）/ AI 生成（Suno 等，必须确认商用条款）/ 委托作曲
风格纯音乐、无人声、克制（不要史诗管弦，那是 4X 游戏）
动态按城市规模分层（见下）

⭐ 分层音乐：这比"一首曲子循环到底"高级得多

城市阶段音乐构成
村（<3000）几乎没有 BGM，以环境音为主（风声、虫鸣、狗叫）
镇加一层简单旋律（吉他/钢琴独奏）
县加入弦乐与低音
市（>30万）完整配器

⚠ 实现上是同一首曲子的多层轨道（stems）按规模渐入，不是四首不同的曲子。 这样过渡自然，且素材量只有一首的 4 倍轨道数。

⚠ 这个设计的意义：玩家会在不知不觉中感觉到"我的城市长大了"—— 不是靠数字，是靠声音变厚了。这是很划算的情绪设计。

7.4 演唱会 / 演出：人声怎么解决

「除非还是刚才那个演唱会，需要人声。」

关键判断：演唱会的声音不需要"听懂唱什么"，只需要"知道有演出"。

层内容做法
音乐主体低频轰鸣 + 鼓点免版权音乐，低通滤波（像从场外听到）
人声模糊的吟唱/和声免版权 vocal 采样（不需要歌词）
观众欢呼、合唱、哨声采样循环
空间大混响 + 远处衰减混响处理

⚠ 不要试图用 TTS 唱歌：歌声合成（SVS）是另一门技术，TTS 念白做不出演唱效果。 用免版权的人声采样 + 效果处理就够了——因为你听到的本来就不清晰。

⚠ 现场演唱会从场外听，人声本来就是模糊的。这一点让"没有歌词"完全不成问题。

七·五、电影相机与拍摄模式（2026-11-17 新增）

7.5.1 ⭐ 一句话原则：慢镜头由玩家主动触发，不由系统打断

谁决定场景
玩家主动（热键即可，不进菜单）任何时候——想拍就拍
系统自动（节日）只在那几天，且可关（09-core-tick §5.5.7）
⚠ 冲突时玩家主动优先。玩家按了慢镜头，节日的自动设置不覆盖

⚠ 不设"慢镜头额度"：玩家想拍多久拍多久。 ⚠ 不弹窗问"要不要看"：玩家按了才有，不按就没有。

层内容批次为什么分层

7.5.4 ⚠ 10x 超快进：延时摄影的代价

拍"城市生长"的延时，需要比 3x 快得多。但：

速度后果
1x / 3x模拟完整（11-scale.md §6.3）
10x月度摊平失效（66 ms × 10 = 660 ms/日），会卡顿，模拟精度下降

⇒ 规则：

  1. 10x 只在拍摄模式里可用，正常游玩上限仍是 3x
  2. 进入 10x 时明确提示「10x 会降低模拟精度，适合拍摄，不适合正常游玩」
  3. 存档打标记（同 sandbox_flags 思路），该档不记录里程碑/成就
  4. 卡顿可以接受：录屏是"拍下来后期加速"，不是"实时玩"

⚠ 不要为了 10x 优化模拟：那是把拍摄需求当成游玩需求，会让整个预算体系变形。

⚠ zoning 不直接引用模型文件，只引用 archetype 枚举值（u8）。 模型路径的解析全在 view/ 侧——这样换模型不用动模拟层（宪法 L2）。

九、验收点

#断言怎么测

AR4同一 archetype 的 1000 个实例只产生 1 次 draw call（按区块）Godot 帧调试器
AR55 万栋建筑在 30 fps 下稳定（11-scale.md §六 预算）probe_tick

⚠ AR6 / AR7 是"画质"的可执行定义（2026-11-22 补）： 不追求"像照片"，追求"截图能直接发出去"。这两条不过，就不要急着加更多建筑原型—— 先修模块化与 LOD，因为糊成一团通常是尺度与合批问题，不是材质问题。
