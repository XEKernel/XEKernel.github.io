二、用地分类：用国标，不用 RCI 三色

这是"中国版"最容易被忽略、性价比最高的一处。
CS 只有住宅 / 商业 / 工业三色；中国的城市用地分类有 8 大类。
用国标分类，玩家的每一个分区决策都立刻带上中国语境。

2.1 可玩版取 6 类（GB 50137-2011 的简化）

代码名称可分区典型内容对应 archetype
R居住用地✅独院、多层排楼、高层板楼/塔楼vlg_court county_walkup city_slab city_tower
B商业服务业设施用地✅底商、商业街、综合体、写字楼town_shop city_podium mall cbd_office
M工业用地✅标准厂房、仓储factory（需补）
A公共管理与公共服务用地✅学校、医院、行政school（+ 医院/政府待补）
U市政公用设施用地✅水厂、变电站、燃气站、污水厂utility_plant（需补）
G绿地与广场✅公园、街头绿地、广场park（需补）
S道路与交通设施❌道路、站场、停车场由 02-road 产，不可分区
E非建设用地❌ 禁建基本农田 / 林地 / 水域 / 郊野farmland forest water

⚠ E 不是"一种分区"，是"禁建层"：玩家不能对它做分区，只能征收置换（占补平衡，F39）。 它同时承担"耕地红线"与"菜篮子供给"两个角色（12-china-features §11.2）。

⚠ 不做的三类（推到 DLC / 打磨年）：W 物流仓储（并入 M）、 A 的细分（体育/文化/医疗先只做学校）、特殊用地（军事/文物）。

2.2 为什么这事重要

CS城脉

商住关系分离B 类含底商与写字楼，住宅区必然带底商（真实中国）
公共设施服务建筑单独盖A 类用地，要占指标
市政设施水管电线（烦）U 类用地（有占地成本，见 07-services §四）

2.3 子类：工业四门类、商业四形态

用户 2026-11-15：「工业也分很多类……而像中国这种全产业链国家工业门类就更多了」
「商业也分很多种，比如菜市场、农贸市场，还有娱乐性的商场、小吃街等」。

M 工业：按产业链功能分 4 类（不按国标 41 个大类，也不按 CS 的"农林油矿"）

子类名称服务谁特征
M0资源开采（煤矿 / 铁矿 / 油气井 / 稀土矿 / 砂石场）原料供给全链只能建在资源点上；有储量与年产量；采完枯竭；采煤有沉陷区后果（F71–F73）
M1建材工业建造（水泥/钢材/混凝土）占地大、需货运、决定全城建设速度
M1b化学工业（石化 + 煤化工 + 化肥）塑料/化纤/化肥/焦炭可技改"减燃料增化工"（F90）；高耗水、高碳
M2消费品工业商业供给（食品/轻工）中等占地，就业密集
M3装备与电子高薪岗位需技能人口，土地产出高
M3h高新技术产业（推打磨年）高附加值、高税收需通信覆盖 + 高技能人口 + 快速路；高新区形态见 12-china-features §11.3

⚠ M1 是唯一会反向影响 zoning 自己的子类：建材产能不足 → 工地停工（见 12-china-features F60）。 这是全场唯一"工业制约城市生长"的闭环。

三、小区：中国住宅用地的组织方式

这一节回答"为什么中国城市看起来是那个样子"。
封闭式小区（围墙 + 大门 + 门禁 + 内部道路 + 内部绿地） 是中国住宅最独特的形态，
也是 CS 完全没有的东西——CS 的住宅直接临街。

3.1 三级组织（GB 50180-2018 的生活圈）

层级规模空间特征
居住区（15 分钟生活圈）3–5 万人3–5 km²，含中学、社区医院、商业中心
小区（10 分钟生活圈）1–1.5 万人0.5–1 km²，含小学、菜市场、围合边界
组团（5 分钟生活圈）0.2–0.5 万人内部绿地、儿童活动场地

⚠ 2018 版把 90 年代的「居住区—小区—组团」改成了「生活圈」，这是断代点（gb-standards.md §二）。 code_era &lt; 2018 的用地按旧三级，&gt;= 2018 按生活圈——两套空间逻辑不能混用。

3.2 一个小区实际的构成：沿街门面 + 内部住宅

⚠ 2026-11-15 修正。 我原先写成"四周围墙 + 一两个大门"，用户按实际观察纠正：
**「小区内部为住宅楼，外部为门面，可以开店等，当然也不是完全被门面包围，
有的甚至就在商场旁边，一些约束等可能还需根据实际来修改。」**
⇒ 真实形态不是"围墙包围住宅"，而是 "沿街一圈商铺 + 内部住宅 + 局部围墙"。

生成顺序（这个顺序决定形态）

按沿街面宽细分 parcel
   ↓ ① 沿街第一圈（frontage strip，进深 12–18 m）→ B 商业（底商）
   ↓ ② 内部（interior）                    → R 住宅
   ↓ ③ 剩余边界：有门面的段 → 商铺外墙；无门面的段 → 围墙
   ↓ ④ 主入口开在无门面的段上（通常 1–2 个）
要素规则
沿街门面只在临主街/次干道的一侧生成；支路、背街常常没有
门面进深12–18 m（一间铺面的真实尺度），不是整块地
门面占比不包围全部边界。转角、背街、临河道的一侧通常是围墙
商场旁的例外临近 mall 的住宅地块，门面让位给商场，这一侧只有围墙或直接贴商场
围墙只出现在没有门面的边界段上，因此天然是"断续的"

⚠ 这一条让画面立刻变真实：中国小区的墙不是完整一圈，而是"有店的地方是店，没店的地方是墙"。 CS 那种"整片均匀"的做法永远做不出这种参差感。

四条硬规则

#规则后果
1围墙 / 门面沿 parcel 边界生成，主入口只开在围墙段街区内部不连通 → 降低局部可达性（R1 的直接来源）
2内部道路不进入公共路网玩家要算"绕行距离"，不能穿小区抄近路
3绿地率按国标（新区 ≥30%，旧区 ≥25%）占地，挤压容积率
4出入口数量受限（1–2 个）出入口太少 → 高峰期出入口自身拥堵

⚠ 规则 1 和 4 是"超大街区"痛点的机制来源：玩家会本能地想建一个 500 m 见方的大小区， 然后发现所有人挤在一个大门进出——这就是中国城市的真实体验。

⚠ 但门面把"绕行"这件事变复杂了：沿街门面本身是可达的（人可以走到店门口）， 只是不能穿进小区内部。所以可达性计算要区分"沿街可达"与"内部可达"，不能一刀切。

3.3 非封闭形态（同样要有）

形态出现在特征
独院农房村庄每户自带院墙，无统一大门
沿街自建镇贴红线，底层商铺 + 上层住宅（同一栋楼），无院
老单位大院县（code_era 60s–90s）大围墙 + 内部公共建筑，门面极少
开放式街区新区试点无围墙，小街区（政策 2016 后提倡，实际少见）
临商场的住宅市一侧直接贴商场，这一侧无门面、无围墙（用户观察到的例外）

⚠ 上表说明"约束要按实际调"：这五种形态在同一个城市里能同时存在， 所以 03-zoning 的参数不能是一组全局常量，必须是按 parcel 的属性组合（沿街等级 + 邻居类型 + code_era）。

三·五、地块内部布局：五种原型 + 参数，不是随机（2026-11-16 新增）

用户提出的难题：「我们用道路把一块地围起来的时候就可以直接把这块地设为指定区域，
比如小区、商场、工业区等，但是现在有一个难题，不同小区的内部道路以及建筑布局是不一样的，
程序化生成植被、配套设施以及住宅楼貌似不好搞，得玩家手动来放。」

3.5.1 先算一笔账：手动放不可能

项数量（1000 万人口）
住宅建筑约 3 万栋
parcel50 万–200 万
玩家一局的操作次数（现实上限）几千次

⇒ 3 万栋楼一栋一栋摆，不可能。 必须程序化。 但"程序化"不等于"随机"——随机生成的小区一眼假。

3.5.2 ⭐ 关键洞察：日照规范已经把选择空间压死了

中国小区的行列式布局，不是设计师选的，是被《城市居住区规划设计标准》逼出来的。

约束后果
住宅必须南北朝向（否则拿不到日照）楼只能横着排，不能随机转角度
楼间距 ≥ 日照系数 × 楼高（gb-standards §三）间距被高度决定，不是自由的
地块形状由路网围合（R6）排布必须贴合不规则多边形

⇒ 能自由变的只剩三件事：排列方式、楼型（板/塔）、绿地与出入口位置。

这就是为什么这件事"没那么难"：约束已经把解空间从"无限"压到"几十种"。

3.5.3 五种布局原型（覆盖 95 % 的真实情况）

原型名称出现年代生成规则形态描述
P1行列式1990 至今（主流）沿长边方向平行排板楼，间距由日照算出一排一排，整齐，最"中国"的居住形态
P2周边式1980 前（单位大院/老城）楼沿地块边界围一圈，中间留院子沿街一圈楼，内部是院
P3点式2010 后（新区高端）塔楼错落布置，间距大，中间大块绿地几栋塔楼散在绿地中
P4外板内塔2000–2010外围板楼 + 中心塔楼外圈板、中间塔，密度高
P5自建/城中村任何（unplanned）见缝插针，跳过规范校验无规则、握手楼（DLC3 才载入）

⚠ P1 行列式是全世界最"中国"的居住形态。苏联东欧也有板楼行列，但中国的更密、 更长、更连续（因为容积率更高、地块更大）。这一条比任何装饰都更能一眼认出"这是中国"。

3.5.4 玩家能控制的三层粒度

层玩家做什么何时做
选原型在地块上选 P1–P5（默认按 code_era 自动选）划区时
调参数间距档（紧凑/标准/宽松）/ 绿地率（25/30/35 %）/ 出入口数（1/2）划区时或之后
微调拖动单栋、删一栋、补一栋推打磨年，本体不做

⚠ 微调推后是对的：本体先把"划一片地就能长出一片像样的小区"跑通， 微调是给追求细节的玩家的，不是必需品。

3.5.5 什么程序化、什么手动（划清楚）

内容谁负责为什么
住宅楼的位置、朝向、层数程序化（按原型 + 参数）3 万栋，不可能手动
内部道路程序化（沿楼间空隙生成）跟随楼位自动生成
绿地/植被程序化（填充剩余空间）低价值，程序化即可
围墙与大门程序化（§3.2 已定规则）—
学校 / 菜市场 / 变电站玩家手动点放它们跨地块服务，不属于某个小区
商场 / 工厂主体玩家手动点放（单栋大体量）不是"排布"问题，是"放一个建筑"

⚠ 这条分界很重要：排布类的程序化，设施类的手动。 把学校和菜市场也纳入"小区自动配套"，会让玩家失去"我要在这个片区建一所学校"的决策感。

3.5.6 ⚠ 一条必须守住的规则：改原型不许"瞬间变形"

行为结果
玩家改布局原型 / 参数只影响未来生长的建筑
已有的楼完全不动，要改只能拆了重建（走施工期）

⚠ 理由：城市的可信度来自"历史累积"。如果玩家一改参数，整片小区瞬间重排， 那这个城市就不是长出来的，是"调"出来的——这一点会毁掉整个游戏的质感。

3.5.7 实现落点（不新增文件）

⚠ 布局生成算法并入 parcel_subdiv.cs，不新建文件（DG5 ≤3 文件；R19：sim/ 为 C#）。

理由：它和 parcel 细分是同一条链条—— block_face →（细分）parcel →（布局）building，两次都是"把空间切成更小的单元"。 拆成两个文件反而是人为切断。

三·六、小区不是"一堆楼"，是一个整体工程（2026-11-16 新增）

用户的实际观察：「建造一个小区的时候其实是建造一个整体大建筑。
首先都是先挖地基，并且挖得较深，毕竟是作为地下停车场；
然后分别在要建楼的地方开始铺设钢筋。
其实我们在小区地面上看到的绿化都是后期做的，而且还是在巨大的"混凝土壳"上，
然后"混凝土壳"上面有住宅楼、社区服务中心以及道路等。」

3.6.1 为什么必然是"整体"而不是"逐栋"

原因说明
地下车库必须连成一片车库是整块底板，不能一栋楼一个坑——车要能开过去
深基坑只能挖一次挖 8 m 深的坑，做整体地下室结构，再回填。逐栋挖等于把坑填了再挖
顶板就是地面地库顶板（用户说的"混凝土壳"）就是小区的地面层，上面做覆土、道路、绿化
管线要走底板水电气主干都在地下室，逐栋建没法规划

⚠ 这条推翻了我原来的模型：parcel → building[] 缺了一个中间层。 正确层级是 parcel → compound（小区）→ 底盘 + building[] + 覆土层。

3.6.2 compound 结构（新增中间实体）

字段内容
id / parcel_id—
pit_depth_dm基坑深度（通常 8–12 m，地下两层）
parking_slots地库车位数（不占地面，这是关键）
podium_roof_area顶板面积（≈ 地块面积）
cover_soil_dm覆土厚度（1.0–1.5 m）← 决定能种什么
community_room_m2社区服务用房面积（政策要求 30–100 m²/百户）
building_range地上的楼（住宅 + 社区中心）
internal_access内部道路等级：0 无（只贴围墙）/ 1 有一条环形消防车道 / 2 完整内部路网。⚠ 内部路一律不生成 segment（§3.6 规则 2），此字段只供可达性与消防校验用
stage施工阶段 0–4（见 §3.6.3）

3.6.3 四个施工阶段（每阶段视觉完全不同）

阶段名字工期画面副作用
0挖基坑6–12 月一个大坑 + 土方车排队渣土车穿城、扬尘、夜间运输
1地下室结构6–12 月坑里铺满钢筋、混凝土泵车占道施工
2地上主体12–24 月塔吊群（一小区几台到十几台）+ 逐层升高噪音、遮挡
3覆土与配套3–6 月回填土、铺路、种灌木、砌围墙—
4交付—完整小区—

⚠ 阶段 0 的渣土车是中国城市最日常的景观之一，也是交通压力的真实来源 （工地周边道路被重卡碾压、夜间运输、限行时段）。这条可以接 traffic 的货运 OD。

⚠ 阶段 2 的"塔吊群"是"中国工地"的核心视觉符号（F7）。一个 500 m 见方的小区 同时有十几台塔吊——CS 全球都没这种画面。

3.6.4 ⭐ 覆土厚度决定绿化：为什么中国小区"树不大"

覆土厚度能种什么中国小区的实际情况
< 0.6 m只有草坪、地被屋顶绿化
1.0–1.5 m灌木 + 小乔木绝大多数小区（地库顶板）
> 2.0 m可种大树少数无地下室的老小区、公园

⚠ 这是一个非常真实的物理约束：地库顶板承重有限，覆土不能太厚， 所以中国小区里大树少、灌木和草坪多——不是设计品味问题，是结构问题。

⇒ 做成规则：绿化类型 = f(cover_soil_dm)。老小区（无地下室）能种大树， 新区（大地盘）只能种灌木。这个细节一做，画面立刻不一样。

3.6.5 对"停车难"（F41）的连锁修正

原来现在（更真实）
停车要占地建停车场停车位藏在小区基坑里，不占地面
地面停车占车道 → 通行能力 −25 %老小区（无地库）才这样，新区不占

⚠ 这解释了一个 CS 做不出的画面：中国小区地面看起来很空（全是绿化和小路）， 但车很多——车都在地下。

⚠ 但地下车库不等于免费：深基坑造价极高（占开发成本 20–30 %）。 开发商愿意挖，是因为车位能卖钱（这也是土地财政的一部分：地下空间也是资产）。

⚠ 老小区（1990 前）没有地库 → 车只能停地面 → 占车道 → 拥堵。 这就是"老城区更堵"的一个真实来源。

3.6.6 按年代分：大地盘不是从来就有的

code_era基础形式停车绿化
1960–1989独立基础，无地下室地面停车 / 自行车棚直接种地，可种大树
1990–2005部分有半地下少量地面 + 半地下大树较多
2005–现在大地盘 + 地下车库全地下覆土 1.0–1.5 m，灌木为主

⚠ 这条完美呼应 R4 的"年代层理"：同一座城市里，老小区的树比新小区大。 玩家一眼就能看出哪片是新开发的。

3.6.7 分期开发（不要一次全建）

真实小区是一期、二期分开建的。所以：

规则说明
compound 可分 2–4 期每期独立走 §3.6.3 的阶段 0–4
后期不重新挖基坑二期沿用一期地库（如果连通），或独立小基坑
分期之间地面是完工的玩家能看到"一期住人了，二期还在挖坑"

⚠ 这比"一次建成"真实得多，也让工地景观持续更久（十年里一直有塔吊）。

三·七、地块会切分、合并，建筑会扩建（2026-11-23 新增）

开发者原话：「实际的建筑大小并不是确定的，有的厂会扩大，或者一些地要切分或者合并。」
R6 定义的 parcel 生成规则（道路围合面 → 按沿街面宽细分）只回答了「一开始怎么切」，
没回答「之后还能不能变」。真实城市里地块边界和建筑体量一直在变，这一节补这一层。

3.7.1 四个会变的东西（别混在一起）

维度现实里的例子谁改频率允许
parcel 边界（切分 / 合并）一宗地分家、开发商整片拿地系统（地价/开发强度触发）+ 玩家（更新工具）低频✅ 但必须有手续与施工期
建筑 footprint（占地）厂区加建厂房、仓库系统（布局原型 / 扩建）中✅ 受退线与日照约束
层数（升层 / 加建）老小区加装电梯、城中村自建房升层系统中✅ 受限高与日照约束
用地性质工业转住宅（退二进三）玩家（更新）+ 政策极低频✅ 见 §五 生长与废弃

⚠ 不是所有"变大"都叫扩建：厂区在自有宗地内加建 ≠ 拿邻居的地。后者是合并，要钱、要补偿、要走流程。

3.7.2 切分与合并的硬规则（写死，不许自由发挥）

#规则为什么
1切分后每宗必须同时满足 min_frontage（沿街面宽） 与 最小面积否则会出现 2 m 宽的"面条地"，无法建任何东西却占着数据
2合并上限 max_parcel_area防止一宗地吞掉整个街区，让地价与开发强度失去意义
3只能沿既有分界线或道路切/并，禁止斜切出新边界斜切会让 parcel 数据集不可复现，存档迁移必炸
4切分/合并后旧 parcel_id 失效，记墓碑（split_from / merged_into）存档、OD、地块史都要能回溯；id 直接复用会造成幽灵引用
5在月边界结算，不允许日内随机时刻发生与 R30（OD 月边界算一次）同一条纪律，否则同一存档两次跑结果不同
6每宗地的切分次数有上限（建议 3 次）防 parcel 数量爆炸；到顶后锁定，只能合并不能切
7切分/合并必须有施工期（围挡 / 工地 / 分期）呼应 §3.5.6"改原型不许瞬间变形"——城市不会在一帧里改完边界

⚠ min_frontage / 最小面积 / max_parcel_area 具体数值待核对国标与地方规定（reference/gb-standards.md 现有条目多数标了【推测】）。未核对前不得写进 config/sim/（R4 纪律）。

3.7.3 什么时候会自发发生

切分（一宗变多宗）常见触发：

  • 地价涨到高于"整宗持有成本" ⇒ 小地块更好卖（老城核心区最常见）
  • 业主分家 / 破产分割
  • 旧大厂搬走后，宗地被拆成若干块分别出让（这是中国城市最常见的切分场景）

合并（多宗变一宗）常见触发：

  • 开发商整片拿地做小区（§3.6 的 compound 就是以合并为前提）
  • 厂区扩产要地（用户原话里的"厂会扩大"）
  • 政府主导的成片更新（棚改 / 老旧小区连片改造）

3.7.4 对数据结构的影响（这条最容易漏）

项要求
parcel 字段必须有 version（每次边界变动 +1）、split_from / merged_into、area、frontage
派生栅格（50 m / 100 万格）边界变动后必须能局部重建，不能全图重算（B2 性能线）
存档边界变动是事件，要能回放；不支持回放就等于每次读档城市都不一样
OD / 交通地块变动会改起终点，走 R30 的月边界重算，不在日内改
地带（zone）切分后子地块继承父地块地带；合并时若地带不同必须先统一，否则拒绝合并

3.7.5 视觉与 UI 契约

  • 切分 / 合并 / 扩建都要有可见的施工痕迹（围挡、塔吊、渣土车、分期脚手架），否则玩家会觉得"地图自己变了"
  • 信息视图 land（土地）与 renewal（城市更新）必须能回答：本月有几宗切分、几宗合并、多少面积易主

—— 不显示，玩家就无法理解地价和天际线为什么在变

  • 文保建筑所在宗地：禁止合并进开发地块，只能原址保留或整体迁移（heritage 视图里可查）

3.7.6 验收点（B3 交付时加）

#断言
Z-1切分后每宗都满足 min_frontage 与最小面积；不满足的切分必须被拒绝并给出理由
Z-2切分/合并后旧 parcel_id 不再被任何系统引用（墓碑生效）
Z-3同一存档跑两次，地块边界变更序列完全一致（月边界结算 + 可回放）
Z-4合并两块地带不同的地，必须被拒绝（或先要求统一地带）
Z-5大院型设施扩展范围时，非连续 / 含文保 / 含他人已建 的请求必须被拒绝并给出具体原因
Z-6扩展的征地成本按当时地价结算，且扩展序列可回放（同一存档两次跑结果一致）

3.7.7 特殊建筑（"大院型"）：玩家手动扩展范围（2026-11-23 新增）

开发者原话：「另外一些特别的建筑可以手动扩展范围。」

先说清楚这是另一种东西：普通住宅/商业由 parcel 自动细分生长（系统决定边界）， 而"大院型"设施的边界由玩家划定并可以继续拉——它的内部道路不接入城市路网，边界靠围墙/围挡， 内部布局按自己的逻辑排（航站楼、跑道、教学楼、看台）。

哪些算大院型（共同点：占地大 + 内部路网自成体系 + 边界是墙）：

设施为什么要手动定边界
机场跑道方向与长度决定一切，不能由 parcel 细分生成
火车站 / 高铁站站场 + 广场 + 存车线，形状完全非规则
大学 / 职教园区围墙内自成一体，内部道路不给城市用
三级医院 / 医学中心院区 = 若干栋 + 内部环路 + 后勤区
体育中心 / 会展中心场馆 + 集散广场，日照与退线规则不同
大型厂区（化工、钢铁、汽车）工艺流程决定布局，用户说的"厂会扩大"就是这一类
公园 / 植物园 / 主题公园边界即围墙，内部是园路
污水厂 / 电厂 / 垃圾焚烧厂卫生防护距离决定边界，不是容积率决定

3.7.8 扩展范围的机制（六条）

#规则理由
1扩展 = 把相邻宗地合并进该 facility（复用 §3.7.2 的合并规则与 parcel_id 墓碑）不要为"大院"另造一套空间模型，否则存档与 OD 会有两套真相
2必须连续（不能飞地），且新增部分必须是空地或可征收（非文保、非他人已建）飞地会破坏路网/管线拓扑；文保禁扩是同一条底线
3扩张要付钱：征地成本 = 地价 × 面积 × 系数 + 安置补偿中国城市的"大院扩大"本质是征地，不是免费涂色
4单次扩展面积 ≤ 原面积的 50%，且在月边界结算防止一把拉成巨无霸；与 R30 同一条纪律
5有施工期与分期：围挡推进 → 场地平整 → 内部路网 → 单体呼应 §3.5.6"不许瞬间变形"
6扩展后内部道路/管线按新边界重排，但不得改动城市路网拓扑大院内网是私有路，不能反过来改公共路网

⚠ 玩家能"缩"吗：可以，但只能是退还（退地），且已建单体不拆——退地后那块地回到可出让池。 ⚠ 不能缩到把出入口切掉：必须保住至少一个对外出入口，否则系统拒绝。

3.7.9 与自动生长的分工（一句人话）

类型边界谁定什么时候变
普通住宅 / 商业 / 小厂系统（parcel 细分 + 布局原型）自动：地价、需求、容积率余量
大院型设施（机场、大学、大厂、公园…）玩家（手动划定 + 手动扩展）手动：玩家掏钱征地，或政策推动
老城存量（城中村、老旧小区）系统 + 玩家（更新工具）半自动：整治/改造触发重划

⚠ 这个分工很重要：如果不分开，要么机场被 parcel 细分成几十个小块（荒谬）， 要么整个城市都得玩家手画（变成画图软件）。

四、容积率、密度与限高（code_era 驱动）

参数作用取值来源
far 容积率决定总建筑面积 → 决定层数地方控规（gb-standards.md §3.5 只给范围）
density 建筑密度底层覆盖率 → 决定"排得有多密"控规，通常 20–35%
height_limit 限高硬上限行政层级（县城 ≤18 层）+ 城市规模
setback 退线建筑退道路红线距离控规，通常 3–10 m

4.1 层数的推导（唯一公式）

层数 = FAR / 建筑密度          （向上取整，且不超过 height_limit）

⚠ 这条公式是 DG9 判据（12-china-features §五）的实现基础： FAR 从 2 调到 6，层数必须可测地变化。

4.2 code_era 如何决定这四项

年代FAR 常见密度限高结果形态
60s–80s（单位大院）0.8–1.225–30%6 层板楼行列式
90s（房改后第一批）1.2–1.828–35%6–7 层密排砖混，山墙相接
00s（商品房兴起）2.0–3.020–30%11–18 层小高层 + 板楼
10s–20s（新区）3.0–5.015–25%33 层 / 县城 18 层塔楼点式，间距大

⚠ 上表是初始手感值，不是国标（国标只给限高与日照，FAR 由地方定）。平衡要跑出来。

4.3 站点催化：TOD 与"高铁新城"（R18 新增）

这是"地铁一响黄金万两"在分区层的落地。
设施半径效果
地铁站500 mfar 上限 +0.5、height_limit +20 %
公交站300 mfar 上限 +0.1（很轻）
高铁站800 mfar 上限 +1.5、人口导入加速、地价跳涨（F31）

⚠ 地铁站的催化和高铁站差一个量级：地铁是"市内可达性提升"，高铁是"城市级的区位改变"。 把两者做成一样强，会出现"每个地铁站都长出一片 CBD"的荒谬画面。

⚠ 催化只提升上限，不强制建设：far 上限高了，但如果没有需求与可达性，楼照样不长。 这条保证"地铁修在没人的地方"不会凭空造出高楼——这正是玩家要判断的事。

⚠ 催化范围不进存档，读档时按站点位置重算（与 coverage_grid 同类，是派生量）。

七、验收点

#断言怎么测
ZN1画出 6 种用地，每种能长出对应 archetype，且不会串（商业不长住宅楼）探针逐类建一块，打印 archetype
ZN2DG9：同一 parcel 把 far 从 2 改到 6，floors 变化 > 2 倍acceptance.gd --case=far
ZN3县城（人口 3–30 万）任一建筑 floors ≤ 18探针断言
ZN4小区生成符合顺序：沿街一圈是 B 商业（进深 12–18 m），内部是 R 住宅，且门面不包围全部边界探针打印一个 block 的用地分布图
ZN5穿小区抄近路不可行：从街对面到小区内部，绕行距离 / 直线距离 > 1.3探针算两组路径
ZN10沿街门面只在临主/次干道一侧生成；支路与背街侧生成围墙探针打印四条边的用地类型
ZN11紧邻 mall 的住宅地块，朝向商场的一侧无门面、无围墙探针 + 截图
ZN12同一块地上 P1 行列式与 P3 点式生成的建筑数量、间距、形态明显不同探针打印两组建筑坐标
ZN13所有程序化生成的住宅满足日照间距（南北向 + 间距 ≥ 系数×高）探针逐栋校验
ZN14code_era < 1990 的地块默认 P2 周边式；≥ 2010 默认 P1 或 P3探针断言
ZN15改布局参数后已建成的楼一栋不动，只影响后续生长探针改参数前后对比
ZN16学校/菜市场只能玩家手动放，程序化布局不会自己生成它们探针断言
ZN17一个小区走完 4 个阶段，每阶段视觉不同（坑 → 钢筋 → 塔吊群 → 覆土）截图四张
ZN18小区建成后车位数 > 0 且不占地面；parking_slots 与地面可用面积无关探针断言
ZN19覆土 1.2 m 的地块长不出大树；无地下室的 1980 年代地块能长大树探针比对两组绿化类型
ZN20分期开发：一期已交付入住（有人口）时，二期仍在施工阶段探针 + 截图
ZN211980 年代地块没有地下车库（pit_depth_dm = 0），且地面停车占道探针断言
ZN6升级走"拆除重建"：state 经历 construction，且期间有塔吊探针 + 截图
ZN7绿地率：新区 R 类 parcel 的绿地占比 ≥ 30%探针统计
ZN8存档 → 读档后 parcel 的 id 与 use_code 完全一致探针断言
ZN9工厂外迁后 3 年内建筑转为废弃状态探针快进

  • 2026-11-16（三）：新增 §三·六 小区是一个整体工程。

依据用户对本地小区施工的实地观察「先挖深基坑作地下停车场 → 各处铺钢筋 → 地面绿化是后期做的、而且在巨大的"混凝土壳"上 → 壳上面才是住宅楼与道路」： ⭐ 推翻原 parcel → building[] 模型，新增中间实体 compound（底盘 + pit_depth / parking_slots / cover_soil_dm / community_room / 四阶段 / 分期）。 三个连带发现： ① 覆土 1.0–1.5 m 决定了"中国小区树不大"（地库顶板承重有限，只能种灌木）； ② 车位藏在地下 ⇒ 地面看起来空但车很多，且老小区（无地库）才占道拥堵； ③ 大地盘是 2005 后才成为标配，1980 年代是独立基础 → 同城新老小区的树有大小差别。 新增 ZN17–ZN21 五条断言。
