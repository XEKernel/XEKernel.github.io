v2 子代理协作规范

📌 涉及性能取舍时，结论统一登记在 docs/design/19-tradeoffs.md；本文只说明"要什么"，不重复决定"砍什么"。
默认不开子代理。 单人 + 一个 AI 的瓶颈是集成，不是产出速度。
只有当"两个任务改的文件完全不重叠、且不互相等"时才开第二个。
本文是工具无关的契约 —— 无论用 Trae CN / dsh「项目组」/ opencode / WorkBuddy，
规则都一样。落地方式见 §九。

一、什么时候才开

情况开不开
一个系统内的实现❌ 不开，单会话更快
B4 的人口 + 财政（改的目录不重叠）✅ 可开 2 个
B6 的地价 + 学区⚠ 有耦合（地价依赖学区评分），建议串行
查资料 / 读别人的代码✅ 可开（只读，无冲突风险）
"帮我整体优化一下"❌❌ 绝对不开，这是 v1 变乱的起点
任何批次上限 3 个，超过就变成互相等

二、怎么切：按目录，不按功能

⚠ 派活前必须先读 design/system-boundaries.md：它写清了每个系统
"拥有什么数据 / 读谁 / 写谁 / 走哪个 bus key / 文件清单 / 运行频率"。
本文件的模板只是格式，边界以那张表为准。
✅ 正确：子代理 A 只写 scripts/sim/population/（2 个文件）
✅ 正确：子代理 B 只写 scripts/sim/finance/（3 个文件）
❌ 错误：子代理 A 做"人口与就业"，子代理 B 做"财政与土地"  ← 按功能切，会交叉改文件

判断标准：两个子代理的产出文件列表有没有交集。有交集就不能并行。

二·五、语言分工（2026-11-17，R19）

层语言派活时的注意
scripts/sim/ core/C#（.cs）⚠ 禁 Vector3，用 float[] / int[]
view/ ui/ tools/GDScript（.gd）照旧

⚠ R32（2026-11-22）：不要给子代理提"用 Rust 重写某系统"这类任务。 C# 已在预算内（月结 71 ms / 400 ms）；Rust 只允许按三门槛局部下沉，且不进每帧路径。

⚠ 子代理写错语言会直接编译失败——派活提示里必须写明后缀。

⚠ C# 侧三条硬约束（11-scale §6.4 实测）：

  1. 空间数据用 float[] / int[]，不用 Vector3（纯数组快 21 倍）
  2. MultiMesh 用 Buffer 批量写，禁用逐个 SetInstanceTransform（快 9 倍）
  3. 月结里不许 new 对象（GC 会卡帧），用数组池 + struct

⚠ 跨语言只传整块数组：bus 若承载大数组（如 agent 位置）， 一次传一个 float[]，不要在 GDScript 里 for 循环逐个 get。

二·五·五、接到"新现象"时：先归类，别急着加功能（2026-11-22）

用户在描述现象（"堵火车""地铁有段在地上""初五商店开门"），不是在下需求。 子代理（或你）不许把现象直接翻译成一个新系统/新文件。

  • 先归到 ../design/12-china-features.md §二·零 的九类之一
  • 能落到已有条目的参数/枚举 ⇒ 不加条、不改接口
  • 真要新规则 ⇒ 走裁定，再改契约卡
  • ⚠ 一旦"想起来一条加一条"，台账会像 v1 一样膨胀到做不完

二·五·六、⭐ 开发者点到的只是样本，不是全集（2026-11-25）

已犯三次，每次都是"只做他提到的几个"，被他指出来再补：
| 他说了什么 | 我做了什么 | 实际应该是 |
|---|---|---|
| 「左侧要有人口分布、年龄结构、噪音、污染…」 | 12 个视图 | 27 个 / 8 组 |
| 「工厂不止钢铁水泥纺织」 | 22 类（平铺） | 按 03-zoning M0–M4 门类 48 类 |
| 「双层高架 / 双单行道 / 塔吊之外还有别的机械」 | 8 个道路模板 + 塔吊 1 个 | 七组道路属性 + 19 类施工机械 |

规则：

  1. 开发者举的永远是例子，隐含"这一类还有什么"。
  2. 收到清单类需求，先问"这个维度的全集是什么"，再问"哪些现在做"。
  3. 找全集用正交分解，不要线性罗列：
  4. 道路 → 横断面 × 标线 × 竖向 × 运营 × 绿化 × 附属 × 对齐
  5. 建筑 → 门类（M0–M4）× 规模（S/M/L/XL）× 年代（era）× 地域（climate_zone）
  6. 设备 → 起重 / 土方 / 混凝土 / 运输 / 辅助
  7. 扩完必须标优先级 P0/P1/P2，否则问题从"漏"变成"做不完"。
  8. ⚠ 反例（自己踩的）：02-road 第一版给了 8 个模板就说"支持组合型道路"，

实际给的是预设，不是属性全集。"我有几个模板" ≠ "这个维度可调"。

⚠ 这条与 §二·五·五 不冲突：那里说"别一想起就加一条"（防膨胀）， 这里说"别只做点到的那几个"（防遗漏）。两者共同的解是：先找全集，再标优先级。

二·六、多子代理并行：靠契约互通，不靠对话互通（2026-11-22）

背景：开发者明确「要多开子代理，但子代理上下文要互通，不然模块之间连不起来」。
"互通"的正确形态不是把聊天记录互相粘贴（越传越乱、越传越长），而是：

四条原则

#原则具体做法
1共享契约，不共享对话每个子代理开工前读 ../contracts/&lt;自己&gt;.md + 直接上游 1–2 张卡；不需要知道别人怎么实现
2契约先冻结，再并行并行前把本次要动的 bus key / 结构字段 / 验收断言写进卡；冻结后并行期间不许单方面改
3改契约必须广播谁改谁负责：提裁定 → 改卡 → 改文档 → 通知所有下游（否则下游会按旧字段写）
4集成者只做三件事合并、跑 acceptance、改 decisions。不替子代理写实现

并行度（沿用 ../plan.md §六）

情况上限
默认1（串行）
B4 / B6（内部有真独立子任务）2
任何批次≤ 3

⚠ 只有"改的文件不重叠 + 不互相等"才开并行。

并行前的"契约冻结"三步（缺一步就会撞车）

  1. 列清单：本次并行涉及的 bus key、结构体字段、断言编号，逐个写进各自的卡
  2. 标归属：每个 key 只有一个写入者（宪法 L1 的数据版）；读的人只读
  3. 写验收：每个子代理的验收命令 + 期望输出，先写再干

反例（v1 就是这么散的）

  • ❌ A 子代理在 population 里加 satisfaction，B 子代理在 services 里也加一个 → 两套满意度，永远对不上
  • ❌ A 改了 bus key 名字但没通知 → B 运行时才崩
  • ❌ 两个子代理同时改 config/sim/*.json → 合并冲突，谁都不敢rebase

交付时的"接口留痕"（并入 §八 报告模板）

每个子代理的完成报告必须多一段：

## 接口变更
- 新增/改名/删除的 bus key：
- 新增/改动的结构字段：
- 受影响的断言：
- 下游需要做什么：

没有这一段 ⇒ 视为未完成，不许合并。

三、派活提示词模板（复制改数字即可）

# 任务

实现 v2 的 <系统名>，只写以下文件，不允许新建或修改其它文件：
- scripts/sim/<系统>/<a>.cs      ← **C#，不是 GDScript（R19）**
- scripts/sim/<系统>/<b>.cs

# 必读（按顺序，读完再动手）

1. docs/design/00-constitution.md      ← 五条铁律，违反直接回退
2. docs/design/<nn>-<系统>.md          ← 本篇设计，是你的唯一需求来源
3. docs/plan.md 的 <批次> 一节          ← 你的验收标准

# 依赖（只通过 bus 读，禁止 get_node）

- 读：bus 的 `<key>`（提供者：<系统名>）
- 读：config/sim/<系统>.json
- 写：bus 的 `<key>`（消费者：<系统名>）

# 不许碰

- core/ 下任何文件（基类与总线冻结）
- 其它 sim/ 目录（只读）
- scripts/view/ 与 scripts/ui/（宪法 L2：sim 不得引用表现层）
- docs/design/ 下任何设计文档（你只能读，不能改）

# 验收（必须实际跑，贴原始输出）

<一条可复制的命令，例如>
godot --headless --path . --script tools/acceptance.gd -- --case=<系统名>

要求输出包含：<具体数值>，且满足 <断言>

# 交付报告（写到 docs/reports/<日期>-<系统>.md）

1. 实际改动/新建的文件清单
2. 验收命令的原始输出（不许只写 PASS）
3. 未完成项 / 已知问题
4. 需要协调者做什么（例如"请把 scenes/sim/<系统>.tscn 挂到 game.gd 的第 N 位"）
5. 你新增的 bus key（如果有）

⚠ 模板里五段缺任何一段，产出就会变回缝合怪。 这是 v1 用 74 个脚本换来的结论。

四、子代理不许做的七件事

  1. 不许改 core/：基类/总线/时钟冻结。需要新接口 → 写进报告由协调者统一加
  2. 不许 get_node("../别的系统")：只走 bus
  3. 不许引用 view/ ui/：模拟层不认识引擎（宪法 §四）
  4. 不许写 _process / _physics_process：只写 simulate(tick)
  5. 不许在代码里写数字：参数进 config/sim/*.json
  6. 不许"顺手优化"别人的代码：发现问题写报告，不直接改
  7. 不许说"基本完成"：要么验收命令跑绿，要么写清哪条没过

五、验收清单（每个子代理提交前自查，9 条）

[ ] extends SimSystem，只重写 simulate()
[ ] tick_interval 与 tick_budget_ms 明确声明
[ ] 没有 import / preload 任何 scripts/view/ 或 scripts/ui/
[ ] 跨系统通信只走 bus，没有 get_node
[ ] simulate() 里没有魔法数字，参数从 config 读
[ ] 验收命令在 --headless 下跑通，并打印关键数值（不能只写 PASS）
[ ] 在 F3 / probe_tick 里能看到自己的耗时行，且低于预算
[ ] 自己的子场景能单独跑：godot --headless scenes/sim/<系统>.tscn --quit-after 60
[ ] 写了完成报告（§三 模板最后一段）

第 6、8 条最容易被跳过，但它们决定"合起来能不能用"。 第 9 条决定协调者能不能安全合并 —— 子代理不能改装配文件，所以"请把我挂在 X 之后"必须由它写清楚。

六、冲突处理

情况处理
两个子代理都要改 core/停。 改成在 bus 里加一条，或由协调者统一改基类
两个子代理都要改装配文件停。 各自建子场景，协调者合并时统一挂
发现别人系统有 bug不改，写报告 + 复现命令
基类接口不够用报告里写「需要什么方法、为什么」
性能超预算先报数字（哪个系统、多少 ms），不要先优化别人的代码
两个人的 bus key 撞名命名一律 &lt;系统&gt;.&lt;字段&gt;，如 population.total

七、已知的坑（17 条 = 13 条 v1 实测 + 2 条跨语言 + 1 条空桩装配 + 1 条别让用户点编辑器）

这些是引擎层的坑，与架构无关，v2 一定还会遇到。先看一遍能省两天。
  1. AStarGrid2D 必须先 update() 再 set_point_solid()，否则每格报一条错，16384 条刷屏像是卡死
  2. --headless 下 get_cmdline_args() 不含 -- 之后的参数，要用 get_cmdline_user_args()
  3. MultiMesh.instance_color 写不进去（读回恒为黑，渲染成纯白）→ 要颜色区分时用「每类一个 MultiMesh + 固定材质」
  4. PanelContainer 不能挂 extends Panel 的脚本，直接运行时报错
  5. anchors_preset = 0 配负 offset_bottom 会得到负高度，面板塌成 0。要配 anchor_bottom = 1.0
  6. RichTextLabel 设完 text 立刻 get_content_height() 拿到旧值，要等一帧
  7. CJK 与拉丁在等宽字体下宽度不同，rpad() 按字符数补空格会错位，要按显示宽度补
  8. 自定义 Autoload 的方法不能叫 tr()：与 Object.tr() 冲突，整个 autoload 编译失败
  9. --script 探针里 autoload 全局标识符编译期不可见（Identifier not found），要等几帧后从 /root/&lt;名字&gt; 取
  10. 在下拉框 item_selected 回调里别直接重建该下拉框所在容器，用 call_deferred()
  11. --script 探针别给变量写引用 autoload 的类型注解，会报 Identifier not found 并让探针死循环
  12. 模拟系统里别直接写 bus.publish(...)，用 SimSystem.bus()：探针模式下 autoload 注册晚于脚本编译。v1 的 probe_game_save.gd 曾因此挂死 4 分钟
  13. 会被改写的 MultiMesh 要在视图层各自 duplicate()，别让 .tscn 共享子资源。

同时实例化两个主场景时，后一个的 _ready 会把共享的 instance_count 重置成 1 → Instance index out of bounds。⚠ 不要用 resource_local_to_scene = true 解决，会触发 Cannot set a buffer on a Multimesh that is a different size

跨语言（等 v2 引入 native 时再看）

  1. 一次调用处理整批，输出完整数组让上层整体赋值。 v1 逐实体回写 70,000 个实体用了 52.98 ms，

Rust 只占 4.59 ms —— 92% 花在边界上。改成 5 次引用赋值后降到 5.70 ms

  1. 换边这类"少量但每 tick 都发生"的逻辑也要留在 native 侧，交给脚本逐个处理会从 5.56 ms 涨到 13.7 ms
  1. 空桩 ≠ 能装配：sim/ 的空 .cs 必须让 *System 实现 ISimSystem（Name 与 Cadence 都写对），

否则要到"注册 8 个系统"那一步才炸。2026-11-22 真踩过：service_system.cs 漏了接口、road/ 没有 *_system 文件 ⇒ 现在由 bench/coretest 的 DG4 断言兜住（8 个系统 + 频率与宪法 §三 一致）。

  1. 别把"该用 CLI 的活"丢给用户点编辑器：Chengmai.csproj / .sln / project.godot 的 assembly_name

都能手写，dotnet new sln -f sln（⚠ .NET 10 默认生成 .slnx，Godot 4.7 不认）也能一次生成。 编辑器点击步骤不可复现、不可 review、写不进交接单。2026-11-22 真踩过：把"创建 C# 解决方案"当成了用户任务。

九、在各工具里怎么落地

工具落地方式注意
