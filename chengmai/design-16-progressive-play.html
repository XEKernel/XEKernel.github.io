16 · 渐进可玩：按城市等级切片，边做边玩

建立于 2026-11-24。开发者原话：
> 「边规划边做游戏边玩，比如我们现在只建模村庄有关的模型，然后继续开发游戏，把村庄模拟的逻辑跑起来，
> 此时就需要存档系统了。然后后面继续做镇、县、市，建筑越来越现代化，等级也越高。
> 然后我们也玩这个初始存档来测试游戏，正好后续做宣传片就用这个存档来拍。」
本文把这个想法落成可执行的方案，并补一个它现在缺的前提（存档迁移链）。
与 plan.md 的关系：不推翻 B 批次，加一层横向切片（见 §六）。

一、先肯定：这个想法解决的是最难修的问题

「一局玩起来没意思」这类问题，只有真玩过才知道，而且是后期最贵的返工。 v1 的失败里有一半是"14 条愿景 0 条落地"，本质就是从没玩过。

这个方案还有三个实际收益：

收益说明
早发现"不好玩"村庄阶段就能验"建第一栋房、看到第一户人搬进来"这件事爽不爽
宣传片素材确实需要一个长期存档。临时拼的档拍出来是"演示"，不是"我的城市"
资产按等级分批与 15-model-inventory 的 P0/P1 排期天然吻合，不用另排
单人开发的心理支撑每 2–3 周都有"能玩的"，比连做 4 个月看不到东西强得多

⇒ 方向采纳。 但下面三件事必须先补，否则这个方案会在第二片就崩。

二、⚠ 前提一：存档迁移链（这是硬前提，不是优化项）

2.1 问题

方案的核心是「同一个存档从村庄玩到市」。这要求存档跨十几个版本存活。

但开发期必然改数据结构：parcel 切分规则（03 §3.7）、人口三层（04）、OD 矩阵（08）、 限制条件（11）……每改一次，旧档就读不了。

现有文档只有 01-playable-definition 一句「格式带 FORMAT_VERSION」，没有迁移框架。 这是缺口，而且是致命的：没有它，V0 的存档到 V1 就打不开了，宣传片方案作废。

2.2 做法（B1 就要落地，不能等"需要了再做"）

组件要求
FORMAT_VERSION单个整数，任何影响存档结构的改动 +1（不许跳号）
迁移注册表migrations: {1→2: fn, 2→3: fn, …}，只写增量，不写"全量重写"
读档流程读到 v_old → 链式升级到 current → 再交给系统恢复
前向兼容存档版本 > 当前版本时拒绝并明确提示（不要试图猜）
回归⭐ 每次改完必跑：用最老的一份 V0 档，在当前版本打开并跑 100 游戏日

2.3 必须接受的取舍（要你拍）

迁移只保证"能打开、不崩、能继续玩"，不保证数值完全等价。

理由很实在：V0 期的人口增长公式和 V3 期不一样，存档里存的是"当前人口"，迁移后没法回溯成新公式下的结果。 强行要求等价，等于要求"公式从第一天就不许改"——那这个项目做不完。

⚠ 所以：宣传片用的那条档，会在每次迁移后"略微变成另一座城"，但它的历史（里程碑、已建成的楼）保留。 这一点先讲清楚，免得拍到一半发现"和上次不一样了"。

2.4 与既有断言的关系

01-playable-definition 的 A9（存档→退出→读档，人口/财政/地价三项完全一致）仍然有效—— 它验的是「同一版本内往返一致」，与跨版本迁移是两件事，不要混。

三、前提二：等级闸门（防止静默出错）

3.1 问题

人口长过 3000 就进镇。但如果镇级的系统/资产还没做，会发生什么？

最坏的情况是：不报错，继续长出一堆"参数对但画面错"的楼。 这会污染存档——等你做完镇级回头看，这条档的历史已经不可信了。

3.2 做法

config/sim/city_tier.json：

{
  "tiers": [
    { "id": "village", "name": "村庄", "pop_max": 3000,   "implemented": true  },
    { "id": "town",    "name": "镇",   "pop_max": 30000,  "implemented": false, "note": "V1 未开工" },
    { "id": "county",  "name": "县",   "pop_max": 300000, "implemented": false, "note": "V2 未开工" },
    { "id": "city",    "name": "市",   "pop_max": null,   "implemented": false, "note": "V3 未开工" }
  ]
}

行为：

情况表现
人口逼近阈值且下一级未实现提前 10% 提示一次（"这座城快装不下了"），不是到点才说
到达阈值且下一级未实现限制在阈值上限，并明确告知"镇级内容未实现"；不许静默继续涨
下一级已实现正常升级，出里程碑

⚠ 这不是临时脚手架，是正式功能：正式版里如果玩家用 Mod 缩小地图，也会撞到这个闸门。

四、前提三：V0 不省工作量，只省"深度"

4.1 容易误解的地方

「只做村庄」听起来像"少做几个系统"。实际不是——

村庄要能玩，需要：

需要来自哪批V0 的深度
时间推进（日/月/年）B1 clock完整（R13/R14 的时间尺度不能浅）
修路（能画，能围合出地块）B2 road只做直路 + 简单曲线 + 村道宽度；不做高架/立交/桥
地块与分区（独院）B3 zoning只做独院农房一种原型 + 沿街自建
人口（家庭、迁入迁出）B4 population完整（这是"活了"的核心，不能浅）
财政（税收、支出、破产）B6a最小可用：人头税 + 建设支出
服务（一个就够）B6a只要小学（或村委会）一项，证明服务机制通
存档B1 save完整 + 迁移链（见 §二）

⇒ V0 = B1 + B2(浅) + B3(浅) + B4(全) + B6a(浅) + 存档(全)。 不是"少做"，是每条链路都先打通一遍。

4.2 ⭐ 哪些能浅、哪些绝对不能浅

这条是防止"快速做村庄"变成"快速挖坑"的关键。

类别项目判断
❌ 绝对不能浅parcel 数据结构（03 §3.7 七条硬规则）、Tick 顺序（09）、bus 契约（宪法 L3）、存档格式与迁移一改就全线返工。B2 是全项目最关键一批，不能为"快"压缩
🟡 可以浅路网类型（只直路+曲线）、建筑原型（只独院）、服务种类（只小学）、UI 面板（只 8 个）加类型不用改架构
✅ 可以先不做地铁、高架、桥、开发区、超高层、文保、DLC 池、环境（污染/季节）与 V0 无依赖关系

⚠ 一句话判据："以后加一个类型"可以浅；"以后要改数据形状"绝对不能浅。

五、四个切片（V0–V3）

5.1 定义

切片城市形态人口必须有的明确不做
V0 村庄独院 + 村道 + 田< 3000独院农房、村道、村委会/小学、水井（供水）、人头税一切城市设施
V1 镇沿街自建 + 十字街3000–3 万沿街自建（底商上住）、镇区路网、初中+小学、卫生院、菜市场、镇政府高架、地铁、高层（>6 层）
V2 县6 层为主 + 老单位大院3 万–30 万板楼、县城限高 18 层、公交+站台、县医院、行政中心、工业区（M1/M2）地铁、CBD、超高层
V3 市高层 + 高架 + 地铁> 30 万高层住宅、写字楼、高架、地铁、CBD、M3/M4 工业都市圈、DLC 池

⚠ 阈值来自 R11 与 03-zoning（county_height_cap: 18 是 2021 县城限高）。

5.2 时间预算（按 R14 的尺度算，不是估的）

R14：1 模拟日 = 3 秒 @1x，1 年 ≈ 1095 秒 ≈ 18 分钟 @1x / 6 分钟 @3x。

段人口年增长假设需要年数@3x 耗时
起步 → V0 上限1000 → 300025%~5 年~30 分钟
V13000 → 3 万25%~10 年~1 小时
V23 万 → 30 万20%~13 年~1.3 小时
V330 万 → 100 万12%~10 年~1 小时

⇒ 从空白到 100 万人口，@3x 约 4 小时。这个节奏对"边玩边测"是合适的： 每片的可玩时长在 30 分钟 – 1.5 小时之间，一次测试刚好一个晚上。

⚠ 增长假设是占位值，实际由 04-population 的拉力/推力公式决定，B4 之后要重算。

5.3 每片的验收（三条，缺一不算）

#验收判据
P-1 能玩连续玩 ≥ 该片预算时长，不崩、不卡死、无报错录屏 + 日志无 error
P-2 能赚财政能由负转正且能持续（说明循环闭合）面板数值可复核
P-3 能升该片存档能在下一片版本打开并继续跑 100 游戏日迁移链实测

⚠ P-3 是这个方案的生命线。前两片过了 P-1/P-2 但 P-3 不过，等于整个方案作废。

5.4 每片结束时必须做"回填"

切片法的最大风险是深度差越拉越大：V0 的临时实现一直堆着，到 V3 已经没人敢动。

⇒ 每片收尾做一次回填：把该片"为快而浅"的实现，换成正式实现，不是往上堆功能。

例子V0 的做法V1 回填
路网只支持直路补曲线 + 围合面生成，并验 V0 存档里的路还能编辑
服务只有小学补卫生院/菜市场，同时验旧档的学校还在
UI只开 8 个面板加到 16 个，布局配置驱动（不是改代码）

⚠ 回填的顺序：先回填"数据形状"的东西，再回填"表现"的东西。反了会返工两次。

六、与既有 B 批次的关系（不推翻，加一层）

6.1 两层映射

B 批次 = 能力批次（纵向：每批做完一个系统）
V 切片 = 可玩里程碑（横向：每片穿越所有系统，但每条都浅）

V0 通过 = B1 ✅ / B2 达到 V0 深度 / B3 达到 V0 深度 / B4 完整 / B6a 最小 / 存档带迁移链

B 批次不取消。 取消会导致"系统做到一半就切走"，那正是 v1 的病。

6.2 已实现的进度落在哪

已完成落在哪个切片
B0 立法 ✅全部（前提）
B1 骨架（core 5 文件、sim 24 桩、UI 三页 + HUD 新布局、三配置全接线）V0 的壳（还差 clock 真跑 + 存档 + 相机地形）
第一批 8 个模型V0 用到 4 个（vlg_court / bus_stop / 后续 shop_street V1 用 / factory V1 用）
第二批 16 个（道路车辆标识）V0 只用 rd_* 里最简的 + 车辆可先不做（村庄没车流）

⚠ 这说明一件事：第二批那 16 个里有一半 V0 用不上（高架、拱桥、隔音屏、公交、信号灯）。 但不用改计划——它们属于 V1/V2，先做出来不亏（这是"提前买料"，不是"提前施工"）。

七、必须承认的三个代价

代价说明缓解
不会更快每片都要打通全链路，比"纵向做深一个系统"慢换来的是"每 3 周能看到东西"，以及早发现不好玩
会返工V0 的 UI/数值到 V3 要改返工集中在表现层（便宜）；数据层靠 §4.2 的"绝不浅"保住
深度差风险各系统深度不一致，越到后面越难收§5.4 的"每片回填"+ §4.2 的红线

⚠ 还有一个不易察觉的代价：测试存档会被"玩坏"。 开发期你会用它试各种操作，某些操作会让城陷入不可逆的困境（比如拆错一片路网）。 ⇒ 从 V0 起就做"分支存档"：主档（干净、给宣传片用）+ 试验档（随便玩）。这条成本极低，别省。

八、待你拍（三项）

#事项我的建议
1V0「能玩」的定义能连续玩 30 分钟不出错 + 财政由负转正 + 人口能长到 3000 并触发闸门提示。不要求"好玩"，只要求"循环闭合"
2存档迁移的容忍度接受"能打开但不保证数值等价"。否则等于要求公式第一天就不许改，项目做不完
3每片的资产范围V0 只做村庄相关 4 类（独院/村道/村委会/水井），城市设施等切片。现有 8+16 个资产里 V0 用不到的先留着

⚠ 第 2 项最关键。你不接受这个取舍，整个方案就不成立——因为"一个存档玩到底"必然跨版本。
