06 · 财政与土地：地价、收储出让、税、债务

依据：decisions.md R7（R2 完整链条 + 拆迁收储进可玩版）/ R1（规模）/ R14（时间尺度）。
本系统承载核心循环的一半（R2），也是胜利条件「不靠卖地、不靠卖资源自持」的判定方。

一、范围

负责不负责
地价 land_value（R1 可达性 + R3 学区 + 环境的合成）可达性（在 road）、学区评分（在 services）
收储 → 一级开发 → 出让完整链条（R7）建筑生长（在 zoning）
税（增值税基 / 契税 / 土地增值税）个人收入（在 population）
债务与月供（F43 城投）资源产量（在 employment）
转移支付（F85）与补贴春节施工停工（在 zoning，读 clock）
tax_self_sufficiency（轨二评级与胜利条件）评级本身（在 core 年边界）

二、地价：一个乘法公式，四项因子

land_value(parcel) =
      base(use_code)                  ← 用途基价（R 最低，B 最高，M/A/U 更低）
    × f_access(accessibility)         ← R1 可达性（幂函数，0.4–1.6 倍）
    × f_school(school_score)          ← R3 学区（仅 R 类生效，0.8–1.8 倍）
    × f_env(环境)                     ← 基础版只有绿地率；污染在 DLC1（R27）
    × f_policy(限购等)                ← 政策旋钮，基础版恒 1.0
因子来源范围
baseconfig，按 use_code（R/B/M/A/U/G）差异 5–10 倍
f_accessroad.accessibility（50 m 栅格）0.4–1.6
f_schoolservices.school_score（exp(-dist/500m) 衰减）0.8–1.8，仅 R 类
f_env绿地率占比0.9–1.2
f_policy政策1.0（基础版）

⚠ 刻意用乘法而不是加法：乘法保证"任何一项为 0 时地价不会变成负的"， 而且因子之间是放大关系（好学区 + 高可达性 = 平方级溢价），这正是中国学区房的样子。

⚠ 系数全部进 config/sim/finance.json（宪法 L5）。

三、土地财政完整链条（R7 的核心）

① 收储（征地/拆迁）      成本 = 现状建面 × 补偿单价 + 农地补偿
        ↓                  ⚠ 玩家出血，不是收入（F81 修正）
② 一级开发               成本 = 通路/通水/通电/平整
        ↓
③ 出让（招拍挂）         收入 = 面积 × land_value × 溢价率
        ↓
④ 后续税收               房产/增值税基，**持续但很薄**
阶段方向备注
① 收储支出有建筑的地块最贵（拆迁）；空地/农地便宜
② 一级开发支出没通路通电的地块卖不出价
③ 出让收入一次性，这是玩家早期唯一的"大钱"（F86）
④ 税收收入持续、缓慢，这才是"自持"的来源

⚠ A6 断言的全部意义在这里：如果只有④没有①，卖地永远赚，"只收税必亏"永远不成立。 收储成本是让这条循环闭合的关键一块。

⚠ 溢价率 = (成交价 − 底价) ÷ 底价，作为市场热度反馈（不单独做成机制）。

三·五、流拍与收储流程（2026-11-17 补）

系统间接合的空白：玩家什么时候能征、征了卖不掉怎么办。

3.5.1 收储的前置条件（三条同时满足）

#条件
1资金够付补偿（不够就拒绝）
2地块在规划建设范围内（没规划不能乱征）
3E 类基本农田需要占补平衡（F39，付出额外代价）

⚠ 第 2 条是防止"乱收储"：如果没有规划约束，玩家会把全城都征了等涨价， 那就不是规划游戏，是炒地游戏。

3.5.2 流拍：这是必须做的机制

土地不是想卖就能卖掉的。 卖不掉有三种原因：

原因判定
底价过高底价 > land_value × 1.3 → 大概率流拍
区位太差accessibility 或 land_value 低于门槛
市场周期全城流拍率连续 2 月 > 40 % → 进入下行周期（推打磨年）
流拍后果说明
保证金不退少量损失
该地块降价后可再挂玩家要判断"降价卖还是等"
连续流拍 3 次该地块自动降为"底价 × 0.8"

⚠ 流拍的机制意义：它让"卖地"变成一个有风险的操作，而不是点击即得钱。 没有流拍，土地财政就没有紧张感。

⚠ 但不要让流拍太频繁：流拍率目标 15–25 %。 超过 40 % 玩家会觉得"这游戏在整我"。

3.5.3 一级开发：不投就别想卖好价

投入效果
通路accessibility ↑ → land_value ↑
通水通电能否建设（utility）
场地平整基础造价

⚠ 顺序很重要：先通路通电，再出让。反过来（先卖地再配设施）会卖不出价， 这是真实的开发逻辑，也是玩家最容易搞错的顺序。

四、收入与支出的完整清单

收入频率说明
土地出让金事件一次性，大额，不可持续
增值税基（企业）月与 employment 产出挂钩
房产相关税月与建筑存量、地价挂钩
资源收入月不可持续（枯竭 + 技术淘汰）
转移支付（F85）月保底，随人口规模递减（越大越不能靠它）
支出频率说明
道路 / 市政维护月与存量设施线性相关
债务月供（F43）月借钱搞基建的代价
公共服务运营月学校/医院/公园
补贴（招商/光伏）月F44
收储与拆迁事件大额

⚠ 维护成本必须真实存在：只算建设不算维护，玩家会无限铺设施然后永远不亏。 这是 CS 里最容易被忽略、也最容易让经济失衡的一项。

五、债务（F43）：土地财政的另一半

项规则
借钱用于基建投资（修路、建新区、建地铁）
月供本金 / 期限 + 利息，固定支出
违约余额为负且超过上限 → 破产（失败条件之一）
上限与 tax_self_sufficiency 挂钩：越依赖卖地，可借越少

⚠ 这条设计的用意：真实的土地财政是"借钱建基建 → 地价涨 → 卖地还债"。 债务是这个循环的引擎，也是它的炸弹。玩家必须一直滚下去。

六、tax_self_sufficiency：胜利条件与评级的共同判据

tax_self_sufficiency = (税收 + 转移支付) / (全部支出)
                       ⚠ 分子**不含**土地出让金与资源收入
值含义
≥ 1.0 连续 12 个月达成胜利条件的一半（配合人口 ≥ 100 万）
0.7–1.0靠卖地/卖资源补缺口 → 不可持续
< 0.7财政危险，随时可能崩

⚠ 这个数字必须能被玩家实时看到（顶栏或财政面板）， 否则"不靠卖地卖资源"这条规则玩家根本感知不到。

八、验收点

#断言怎么测
FN-1顶栏财政数字 = ledger 逐项求和（误差 < 0.1 %）探针比对
FN-2学校建成 12 游戏月内，周边 500 m 地价 +10 % 以上（必须在学期内测）探针两次采样
FN-3完全禁止卖地 12 个月 → 财政必为负探针强制 land_sale=off
FN-4收储成本 > 0，且拆迁地块的成本明显高于空地探针两类地块对比
FN-5tax_self_sufficiency 在只靠税收时 < 1，加入卖地后 > 1探针两支对照
FN-6债务月供是固定支出，且借钱能短期抬高余额探针断点
FN-7维护成本随设施存量线性增长探针两组规模对照
FN-8存档 → 读档后 budget debt ledger 完全一致探针比对
FN-9land_value 不进存档，读档重算结果一致探针比对
FN-10学区因子只作用于 R 类，M/A/U 地块不受影响探针四类对比
FN-11底价 > 地价 × 1.3 时大概率流拍，且保证金不退探针造高价
FN-12连续 3 次流拍后该地块自动降至底价 × 0.8探针
FN-13未通路通水的地块卖不出好价（与配齐设施的地块对比）探针两组
FN-14全城流拍率长期落在 15–25 %（不是 0 也不是 50 %）基准城市长跑

⚠ A6 + F1 是核心循环成不成立的唯一证据：这两条不过， 说明"卖地—建城市—收税"这个循环是假的，游戏只是个画图工具。 ⚠ A5 必须标明"学期内"：暑假期间学生 OD 归零，测不出学区效应（12-china-features §3.3）。

九、待定

  1. 房产税：中国目前没有普遍征收，要不要做？建议做成"政策旋钮"（打磨年），不当默认收入
  2. 土地增值税：计算复杂（按增值额累进），建议简化为固定比例
  3. 转移支付随规模递减的曲线：现在只有 transfer_base，需要一条随人口下降的曲线
  4. 限购/限贷/限价（F16）→ ⚠ 2026-11-22 更正：在 B7，不是打磨年（12 台账 F16 = B7；13 §十三 的六个政策旋钮含它）。f_policy 字段仍要预留
