13 · 玩家循环与游戏逻辑：怎么转起来

前十二篇都在设计"模拟怎么算"。这一篇设计"游戏怎么转"：
玩家怎么操作、什么时候会输、存档怎么活下去、数值怎么调。
依据：decisions.md R13/R14（时间）/ R16（模式）/ R17（编辑器边界）/ R18（地铁）。

⚠ "性能"必须独立成一类，不能塞进"画质"： 它回答的是另一个问题——"我这台机器跑不跑得动"，而不是"画面要多好看"。 混在一起，玩家会以为降画质就是降性能。

⚠ 性能类顶部必须常驻一句说明： 「只影响画面，不影响任何数值。低配跑出来的城市和高配完全一样。」 ——不写这句，玩家会怀疑自己的城市和别人不一样（11-scale §八·六）。

⚠ "需重启"必须标注在选项旁，否则玩家改了没反应会以为坏了。 ⚠ 画质给预设（低/中/高/极高）+ 单独覆盖，不要只给一堆滑块。 ⚠ 其中必须单列一项：「模型精度」（低/中/高/极高） —— 控制模型面数与贴图边长， 对应安装体积 ≈1.5 / 4 / 8 / 15 GB。极高档作为可选下载（不装也能玩）。 设计细节见 15-model-inventory §5.3；⚠ 它同样"只影响画面，不影响任何数值"。 ⚠ 无障碍不是可选项：色盲模式（热力图配色可切）、UI 缩放（1080p→4K）、 长按代替连点（手部不便的玩家）——成本很低，但不做就是不让人玩。 ⚠ 无障碍里没有"字幕大小" —— 本作不做字幕层（§20.7）。

1.6 ⚠ 兼容性：三种"读不了"必须区分

这是最容易做砸的地方——直接崩退或静默读错，玩家会失去整个存档。

情况处理
版本更新（FORMAT_VERSION 升）自动迁移（§6.3）；失败则只读打开 + 提示，不覆盖原文件
缺 DLC⚠ 不拒绝：把该 DLC 的实体冻结（如地铁变"停运"），提示"启用 X DLC 可恢复"
缺 Mod⚠ 不拒绝：Mod 内容降级为占位（灰盒子），提示"缺少 N 个模组"

⚠ 原则：宁可"残缺地打开"，也不要"直接读不了"。 玩家的存档是几十小时的资产，不能因为配置变化就判定不可用。

⚠ 但有一个例外：FORMAT_VERSION 跨大版本且无迁移函数 → 必须拒绝， 明确告知"存档来自 vX，当前版本不支持"。静默读成乱数据比拒绝更糟。

三、玩家操作：三种基本动作

千万人口规模下，操作的基本单位是"片区"，不是"格"（11-scale.md §七 C7）。
动作交互适用
拖笔画线按住拖动出曲线（三次贝塞尔），松手成路道路、地铁线
框选刷区拖矩形 / 圆形刷子（半径可调）6 类用地、拆除
点放设施单击放置，可连续放置同一类学校、水厂、变电站、车站、公园

第五种（随时可用）：慢镜头 / 拍摄模式 —— 一个热键直接进，不弹窗、不进菜单。 玩家想拍视频时随时按下，优先级高于节日的自动放慢（10-presentation §7.5.1）。

第四种（划区时顺带）：选布局原型 —— 住宅地块可选 P1 行列式 / P2 周边式 / P3 点式 / P4 外板内塔（默认按 code_era 自动选），再调间距档与绿地率（03-zoning §3.5.4）。 ⚠ 不需要玩家摆楼：3 万栋楼手工放不可能，但"选一种布局"是可操作的。

⚠ 不做逐格刷：2500 km² = 1000 万个 50m 格，逐格操作会让玩家疯掉。 ⚠ 不做"画曲线高级工具"（如 CS 的 Move It）——那是模组生态的事，不是本体。

3.1 开局 15 分钟应该发生什么（这是最重要的交互设计）

时间玩家做的事系统给的反馈
0–2 min看地形，转动相机地形 + 一句指引"这里适合居住"
2–5 min修一条连接线到省道（引爆点，F87）修通后立刻提示"外部通道已打开"
5–8 min框选一片住宅用地地块变色 + 显示"需求缺口"
8–12 min等第一栋楼长出（瓦房/独院）塔吊 → 建成 → 人口 +3
12–15 min出让第一块地（F86 第一桶金）财政跳一下，玩家第一次"有钱了"

⚠ 这 15 分钟是全游戏最关键的 15 分钟。如果玩家在这里不知道该干什么，后面做得再好也没用。 ⇒ A10 断言（陌生人 5 分钟铺出第一条路）测的就是这一段。

四、建造校验：五道，每道都要给具体理由

玩家点下去但没建成，必须告诉他为什么（不能只是"叮"一声）。

#校验失败提示（示例）
1资金「需要 ¥12.4 万，当前余额 ¥3.1 万」
2地形「此处为水体，不能建造」/「坡度 14 %，超过 8 % 上限」
3规范「此处限高 18 层（县城），当前设计 26 层」/「日照间距不足 2.1 m」
4市政「无供水覆盖，需先建水厂」（B3 阶段不校验，B6b 才生效）
5冲突「与已有建筑重叠」/「此处有基本农田（E 类），需先办理占补平衡」

⚠ 错误提示必须带数字。这是用户长期的偏好（"错误反馈要具体：消息 + UI + 文件路径行号"）， 在游戏里同样成立——"无法建造"是没用的提示。

⚠ 第 4 道必须分阶段：B3 阶段市政视为无限供应（03-zoning §七），否则 B3 验收永远不过。

五、失败判定：三种，每条都要有预警与挽回窗口

01-playable-definition P3 要求"至少 3 种会输的方式"。这里定细节。
失败判定预警（提前 3 个月）还能救吗

满意度崩盘满意度 < 30 % 连续 12 个月「满意度 34 %，已连续 9 月」✅ 修学校/治拥堵

⚠ 三条都必须有连续月份门槛，不能一次触发就结束——城建游戏的乐趣在"救回来"。 ⚠ 宽松模式：破产宽限期 ×3（01-playable-definition §5.1），即从 0 个月拖到 3 个月。

十一、诊断：让玩家知道"为什么不长"⭐

这是城建游戏最大的痛点：玩家画了地，等了三分钟，楼没长，然后不知道自己做错了什么。

11.1 建造校验 vs 生长诊断（两件事，别混）

场景玩家问的谁回答
建造校验"我为什么建不了这个？"五道校验（§四），点击时立刻
生长诊断"我建了，为什么它一直不长？"本节，点击地块时查询

⚠ 前者是"动作被拒绝"，后者是"动作成功了但没结果"——后者更让人困惑。

11.2 诊断原因表（每个 parcel 都能查）

按优先级返回第一条阻碍，不是全部：

优先级原因玩家该做什么
1E 类禁建（基本农田/水体）办理占补平衡，或换地方
2无需求（该用途需求 = 0）等人口长，或改用途

十二、通知：分级 + 防轰炸

CS 的顾问弹窗是全世界玩家的共同吐槽。它的问题不是内容错，是频率和打断。

12.1 三级，只有一级能打断

级内容表现会暂停游戏吗
紧急失败预警（赤字 2 月 / 净流出 3 月 / 债务到期）顶部横幅 + 音效❌ 不暂停

⚠ 任何通知都不暂停游戏。城建游戏的节奏由玩家控制，弹窗抢走控制权是最烦的设计。

12.2 防轰炸三条规则

规则数值
同一类通知 30 秒内合并为一条（"3 处设施故障"）合并窗口 30 s
每分钟最多 2 条重要通知上限 2/min
提示类在玩家连续操作中不发（等空闲 3 秒）空闲阈值 3 s

⚠ 玩家可以一键关掉"提示"级，但"紧急"级不能关（那是失败预警，关了直接输得莫名其妙）。

侧边有一个消息列表（最近 50 条），随时能翻。 理由：玩家在专注建造时会忽略滑入的通知，事后要能找回来。

18.0 ⭐ 关键区别：里程碑是"这个城市的"，成就是"这个玩家的"

19.2 ⚠ CJK 四语：真正的成本在这里

四种 CJK 语言不等于"一套字体"。

项数

日文常用汉字 + 假名≈ 2 136 + 假名
韩文常用音节（谚文）≈ 2 350

问题说明

⚠ 字形差异同一码位在不同语言下字形不同：简体 直、日文 直、繁体 直 内部笔画不一样
⚠ 只装一套字体的后果日本玩家一眼看出"这是中文字形"，像看到用中文写的日文

解法（两条，二选一）：

方案做法代价

⚠ 这是 CJK 本地化最容易翻车的地方：文本全对，但字是"错语言的字形"。 ⚠ 韩文不需要汉字字形，但需要谚文覆盖——合并子集必须包含。

⚠ 总计 ≈ 10–13 MB——在 10–15 MB 量级，可接受，但必须做子集化，否则光字体就 80 MB+。 ⚠ 按语言分语言包：玩家只下自己那一种（中文版约 3 MB）。

19.9 阿拉伯语：暂不做，但布局必须预留

用户：「阿拉伯估计很难。」

确实难，但不做的代价是现在就要付的：

难点说明
RTL 整体镜像不只是文字从右往左，整个界面要镜像（工具栏在右、进度条反向）
双向文本（BIDI）阿拉伯文里的数字和英文仍然从左到右，混排要算法处理
字母按位置变形同一个字母在词首/词中/词尾/独立时字形不同（连写）
字体需要阿拉伯字体（但体积不大）

⚠ 这三样里，只有第一样可以在现在低成本预留：

现在就这么写以后做 RTL 要改
❌ margin_left: 20✅ margin_start: 20
❌ align: left✅ align: start
❌ position.x = 20✅ 逻辑方向偏移

⭐ 用逻辑方向（start/end）代替物理方向（left/right）， 以后做 RTL 只要翻一个开关，而不是改几百处布局。

⚠ 这个预留零成本：现在写的时候换个词而已。 ⚠ 但它只在 layout.json 与 UI 代码里生效——3D 世界的坐标不镜像。

文本能否预生成

「人口开始外流」✅
「财政赤字 12.4 万」❌ 无法预生成（数字任意）

⇒ 播报只说"定性"，不说"定量"；数字由 UI 显示。

⚠ 这是刻意的取舍：如果非要念数字，就得上实时 TTS 或生成几万条音频。 "财政出现赤字" + 屏幕上红色数字，效果不比念出来差，成本差两个数量级。

20.7 不做字幕层（2026-11-20 决定）

决定：不做字幕系统。 理由不是省事，是字幕在这个游戏里没有意义：

声音能写成字幕吗
菜市场叫卖 / 广场舞 / 电动车警报❌ 写不出来 —— 写"远处有人叫卖"是废话，不是字幕

⚠ 第三条是关键：给通知配字幕，等于把 UI 上已有的信息再显示一遍，纯冗余。

⇒ 由此得出一条硬规则：

### ⭐ 任何"只通过声音传达"的信息，都是设计错误。

声音只负责氛围，信息一律走 UI。 这条守住了，没有字幕也不会漏掉任何东西。

语音 + 字幕 + UI 通知UI 通知（唯一） + 语音（可选，纯氛围）

⚠ 这不影响无障碍：听障玩家需要的是信息，而信息在 UI 上。 如果哪天出现"只能听"的信息，那是 bug，不是缺字幕。
