3.3 block_face（R6 的核心产出）

字段类型说明
idu32稳定 ID
vertex_rangeu32, u16顶点（顺序排列，逆时针）
area_dm2u64面积（平方分米）→ 平方米要 ÷100
parcel_rangeu32, u16细分出的 parcel 区间
edge_segmentsu32, u16该面由哪些路段围成（沿街面宽计算的依据）

求面算法：半边结构（DCEL）。

  1. 从每个 segment 生成两条有向半边
  2. 在每个节点按极角排序，做 next/prev 链接
  3. 遍历出所有面，丢弃外部面（面积为负或逆时针判反）
  4. 复杂度和为 O(E log E)，只在玩家编辑时跑，不在每 tick 跑

⚠ 求面必须在 road 里做完，zoning 只接收成品。理由：它是拓扑问题，不是分区问题。

项内容

三·五、画路交互与合法性（2026-11-17 补）

画路是玩家做得最多的动作。它必须是"顺手的"，同时"不许乱来"。

3.5.1 三种画法

画法操作适合自动行为
拖拽曲线按住拖动，松手成路主干、快速路自动生成三次贝塞尔，自动吸附到已有路口
直线段点击两点支路、方格网自动平分车道、自动对齐
延伸从既有路端点往外拖扩张继承原路等级与车道数

⚠ 必须自动吸附：路口没对齐会造成"断头路 + 面求不出来"，玩家会以为游戏坏了。 吸附半径 8 m，吸附时给视觉提示（高亮圆点）。

⚠ 不用"自由曲线"：CS 的曲线工具很强，但那是高级玩家的需求。 本体只做"够用"，复杂曲线交给 Mod（13-player-loop §三）。

3.5.2 合法性：五条，每条都带具体理由

#禁止提示
1穿水体「需要桥梁，当前未解锁」/「跨度 320 m 超出现有条件」
2穿建筑「此处有 3 栋建筑，需先拆除（¥X 万）」→ 允许一键拆除
3穿 E 类基本农田「需要办理占补平衡（¥X 万）」
4坡度过陡「坡度 14 %，超过道路上限 10 %」
5资金不足「需要 ¥12.4 万，当前余额 ¥3.1 万」

⚠ 第 2 条允许"一键拆除"：如果不给，玩家为了修一条路要手动拆 20 栋楼， 体验会崩。代价是钱，不是麻烦。

3.5.3 造价与拆迁

造价 = 长度 × 每米单价(按等级) + 拆迁补偿 + 桥梁/隧道附加
等级每米单价说明
支路 L低3.5–5 m 宽
次干 M2中双向 4 车道
主干 M1高双向 6 车道
快速路 H最高需立交，不能平交

⚠ 快速路不许平交：与任何既有道路相交必须是立交（自动生成匝道或拒绝）。 这条不做，快速路会变成"最堵的路"。

3.5.4 拆除与级联

行为级联
拆一条路四张表同步删 → 受影响的面重求 → zoning 收到"面变了"
面消失其下 parcel 与建筑标记为待处理（不自动删，等玩家决策）
面合并两个面合成一个 → parcel 重新细分

⚠ 面消失不自动删建筑：玩家可能想保留那块地上的房子（变成"飞地"）。 让玩家选，比自动删更安全。

三·六、曲线道路的几何与渲染（2026-11-18 新增，参考 CS1 逆向源码）

用户：「最应该"抄"的是 CS1 的道路修建系统，尤其是曲线道路。说起来简单，
就是画贝塞尔曲线，但是道路也是一个模型，怎么弯曲模型还不别扭也是重点需要学习的地方。」

这是本篇之前完全没写的一节——02-road 只写了图和面，没写"路长什么样"。

3.6.1 ⭐ 数据模型：只存 4 个量，不存采样点

CS1 的 NetSegment 只有这几个几何字段（NetSegment.cs:83–87）：

public Vector3 m_middlePosition;
public Vector3 m_startDirection;
public Vector3 m_endDirection;
// 加上两端 NetNode 的 m_position

三次贝塞尔由它们反推（Bezier3(a, b, c, d)）：

控制点值
a起点节点位置
ba + m_startDirection × k
cd + m_endDirection × k
d终点节点位置

⭐ 存档只存 4 个向量，不存曲线采样点。 曲线在任何时候按 Bezier3.Position(t) / Tangent(t) 现算 —— 存档小、插值永远平滑。 ⚠ 我们如果按"每 2 m 存一个点"来存路，存档会膨胀 50 倍，而且改曲线要重算全部点。

3.6.2 ⚠ 弯曲不是"拉伸模型"，是"沿曲线扫掠断面"

这是本节最重要的一条。两种做法的差别直接决定路"别扭不别扭"：

做法结果
❌ 拿直的静态 mesh，用 scale / rotation 去凑被拉长、接缝错位、边线歪——就是"别扭"的来源
✅ 按曲线重新生成顶点（sweep 扫掠）宽度恒定、边线跟随、贴图不拉伸

扫掠的算法：

for t in 0..1 按弧长等距采样:
    pos  = Bezier3.Position(t)
    tan  = Bezier3.Tangent(t).normalized()
    side = cross(tan, up).normalized()      # 横向
    for each 断面点 p in cross_section:
        顶点 = pos + side * p.x + up * p.y

⚠ 必须按弧长等距采样，不能按参数 t 等距： 贝塞尔的 t 不是匀速的——弯的地方点在疏、直的地方点在密， 按 t 采样会导致弯道顶点过少、直线段顶点过多。

3.6.3 断面（cross-section）：一条 2D 折线

段内容
中心线车道分隔线
车道按等级 2/4/6 条
路缘石混凝土，抬升 15 cm
人行道宽度按等级
绿化带 / 隔离带可选

⚠ 断面模板进 config/sim/road.json，不写死（宪法 L5）。 ⚠ 同一个断面沿曲线扫掠 ⇒ 宽度天然恒定，不会出现"弯道变窄"。

3.6.4 ⭐ 曲率过大就插节点（CS1 的 Bend 节点）

CS1 有两个开关（NetInfo.cs:280–282, 738–740）： m_enableBendingSegments / m_disableBendNodes，以及 NetNode.Flags.Bend。

含义：段内曲率超过阈值时，把一段拆成两段，中间插一个 Bend 节点。

好处说明
每段曲率可控单段弯曲过大时 mesh 会自交、翻面
存档小仍然每段只存 4 个量
附属件可复用护栏、路灯、车道线按段重复

⚠ 阈值要按"最大曲率"而不是"总转角"：一个很长的缓弯不会自交， 但一个很短的急弯会。用曲率半径判定（如半径 < 2 × 路宽 ⇒ 必须插节点）。

3.6.5 ⚠ 交叉口：CS1 不是预制件，是「裁剪 + 条件变体 + 缩放」

⚠ 本节 2026-11-18 修正过一次。 初版写的是"CS1 用预制路口 mesh 按连接数分类"，
这是错的。用户指出「开启无碰撞模组时可以 8 条路接一个路口」，查源码后确认：
机制源码位置作用
m_clipSegmentEnds + GetEndRadius()NetSegment.cs:1594, 1639；NetAI.cs:980段端点在路口处被裁成圆头，路面本身是参数化的
m_minOtherTags / m_maxSameTags / m_maxOtherTagsNetInfo.cs:397–407，[ValueRange(0, 8)]节点装饰件的渲染条件按"连接段数 0–8 + 标签"筛
m_meshScales / m_sideScalesNetNode.cs:600, 717, 1055节点 mesh 按左右矩阵 + 缩放向量适配不同宽度

⇒ 路面之所以能接 8 条，是因为它被"裁"出来的，不是"拼"出来的。

三个要点

① 路面：裁剪，不拼装

每段路在节点处按 GetEndRadius 把端头裁成圆角（info.m_netAI.GetEndRadius() * 1.3333f）。 所有进入该节点的段各自被裁一次 ⇒ 中间自然空出一个"补丁区"， 再由节点装饰件盖住。

⚠ 这个做法对"任意条数、任意角度"天然成立——因为没有"4 向 / 8 向"这种东西。

② 节点装饰件：按连接数条件选变体

NetInfo.Node 上挂着筛选条件（值域明确是 0–8）：

[ValueRange(0, 8)] public byte m_maxSameTags = 8;   // 同标签连接数上限
[ValueRange(0, 8)] public byte m_minOtherTags;      // 异标签连接数下限
[ValueRange(0, 8)] public byte m_maxOtherTags = 8;  // 异标签连接数上限

⇒ 同一个预制体可以挂多个装饰变体（斑马线 / 人行道转角 / 安全岛）， 按"这个路口有几条路接进来"自动选。

⚠ 注意值域是 0–8，不是"任意"：CS1 实际上限就是 8 条。 超过 8 条连接的极端情况会退化。

③ mesh 靠矩阵缩放，不靠多套资源

m_meshScales + m_sideScales 把节点面片拉伸到合适尺寸。 ⇒ 一套 mesh 覆盖所有宽度组合，不是每种路口一个 mesh。

我们的做法（修正后）

项方案
路面✅ 段端点裁剪（clip_end_radius = 半路宽 × 1.33），支持任意条数
节点装饰⚠ 按连接数分档（1 / 2 / 3 / 4 / 5–8），每档一套斑马线与人行道
缩放一套 mesh + 矩阵缩放，不按角度做多套
上限8 条（与 CS1 一致，超过就退化处理）

⚠ 这比"角度档位（30/45/60/90）"简单得多： 角度不用管——因为路面是裁出来的，任意角度都自然； 只有铺装贴花需要按连接数分档，而那是 2D 贴图，成本极低。

⚠ 但仍不做"车道级连接"（见 §3.6.9）：每个车道怎么接到对面车道， 是另一套系统（CS1 有，我们没有）。我们的车在路口按 OD 方向直接转，不做逐车道引导。

3.6.5b 车道级连接：做，但分四级（2026-11-25 重写，R35）

⚠ 本节推翻了 2026-11-18 的旧结论（原文：「不做车道级连接，接受'车不按线走'的代价」）。
开发者 2026-11-25：「车道级连接我觉得可以做一下，毕竟高自由度也是这个游戏的特点。」
旧判断错在哪：它把这件事当成"从零建一张车道图"。
但 08-traffic §3.6.2 早已定"agent 生成时按 OD 方向定车道归属"
（左转靠左 / 右转靠右 / 直行居中）——车本来就在正确的车道上。
缺的只是路口内那一段的连接关系。代价比原估低一个量级。

四级划分（只做 Lv0–Lv2）

级内容做不做谁定
Lv0车道归属（生成时按转向定一次 + 抖动）✅ 已有08-traffic §3.6.2
Lv1逐车道转向集合：每条进口道能左 / 直 / 右 / 掉头中的哪几种（可混行）✅ 必做预设序列（默认）/ 玩家（自由档）
Lv2路口内车道连接：进口道 → 出口道的对应关系✅ 做规则推导 + 玩家覆盖
Lv3段内逐车变道（MOBIL 类）❌ 不做与代表性 agent 冲突，代价高

⭐ 关键约束：lane_links 由规则推导，只存覆盖

这是让代价可控的唯一办法。若全量存盘： 4 进口 × 4 道 × 3 转向 ≈ 48 条/路口，数万路口 = 百万级连接，存档与内存都吃不消。

项做法
默认连接推导（见下表），不存

三·七、桥梁与隧道（2026-11-18 新增）

用户：「还有就是桥梁隧道这些，桥梁除了普通的桥之外还有悬索桥斜拉桥。

CS1 的桥"看着小"，原因很具体：它是把桥当成"一段特殊路面"生成的， 塔高与主缆垂度没有按跨度放大，所以 1 km 跨径的桥看起来也像 200 m 的。

3.7.1 ⭐ 第一条规则：桥型由跨度决定，不由玩家选

这是工程事实，也是玩法设计的关键——它把"选桥型"变成"选过江位置"。

主跨桥型说明
< 60 m梁桥（简支/连续）最常见。城市高架、小河
60 – 300 m连续梁 / 刚构跨江中段、跨深谷
300 – 800 m斜拉桥（cable-stayed）中国最强项。苏通、沪苏通、常泰

⭐ 超线性的意义：跨度翻倍，造价可能翻三倍。 ⇒ 玩家会自然地去找"最窄的过江点"——这就是真实的选址逻辑。

⚠ 通航净空：一个真实的历史约束

3.10.1 问题：现有模型是「一 segment = 一断面」，不够用了

§3.6.3 的断面是一条 2D 折线（车道 / 路缘 / 人行道 / 绿化带），沿曲线扫掠。 但一个 segment 只有一组 class / lanes / lanes_per_dir（§3.2）， 所以一条路只能有一种等级、一种车道数。

以下四种东西用现有模型做不出来：

要做的为什么现有模型不行
带辅道的干道主路 60 km/h + 辅道 30 km/h，是两种等级、两种通行能力
双层高架上层快速路 + 地面辅路，两个路面高程、两套车流
分离式路基（两条单行道）横向相距 4–20 m，中间是分隔带，不是一个断面的中线两侧
混合型（主+辅+非机动车+绿化）断面能表达车道序列，但不能表达"其中一段是独立可通行的路"

⚠ 关键区分：断面内分带 ≠ 可以通行。 一条 4 车道的断面里，车道不各自"可通行"；但辅道必须能独立通行（有自己的限速、自己的车流、自己会堵）。

3.10.2 解法：加一层 corridor（走廊）

一个 corridor = 玩家一次绘制。 它沿一条路径扫掠出 1–3 个 band（带）， 每个 band 是一条独立可通行的路（自己的一套 segment 链）。

corridor（一次绘制，一条路径，一个模板）
  ├─ band 0  主路     off =   0 m   h = 0 m    class=1   60 km/h
  │    └─ part（断面分带，从左到右）
  │         人行 3m │ 非机动车 2.5m │ 机非绿化 1.5m │ 机动车 ×4 │ 中央绿化 3m │ …
  ├─ band 1  辅道右   off = +14 m   h = 0 m    class=3   30 km/h
  └─ band 2  高架     off =   0 m   h = +9 m   class=0   80 km/h
层是什么谁能改
corridor一次绘制、一条路径、1–3 个 band玩家（画线）
band一条独立可通行的路（自己的 segment 链）玩家（模板 / 增删 band）
partband 内的断面分带（车道组 / 非机动车 / 人行 / 绿化 / 停车）玩家（参数化组合，见 §3.10.11）
  • off = 相对路径中线的横向偏移（band 级）
  • h = 相对地面（地形高程）的抬升
  • 每个 band 沿路径生成自己的 segment 链，segment 之间不共享 node（见 §3.10.6）
  • ⚠ part 不是可通行单元——它只是 band 的横截面组成。车在 band 内跑，part 决定"能跑几股道"

3.10.3 必须遵守的五条规则

这几条决定"能不能实现"，不是风格问题。

#规则不遵守的后果
C-1⭐ 只有「贴地且可通行」的 band 产生围合面高架上跨会把地块切成一堆碎条（违反 R6 常识）
C-2每个 band 独立计算通行能力；只有 band 0 是导航主路径辅道和主路混在一起算，堵不堵分不清

参与围合  ⟺  (h - 0) ≤ 0.5 m  AND  kind ≠ 隧道

CSUR 的核心是按"道"修建：每个组件代表一组车道（如 4R = 右侧 4 条、3L5 = 左侧 3 条偏移到第 5 道）， 模块由首尾两端车道组的组合定义（base / shift / transition / ramp）， 所以它能做到"3 车道扩 4 车道时从右侧加，而不是居中"。

CSUR 的能力我们取不取理由
断面按车道组自由组合✅ 取这正是"自定义车道数/绿化/标线"的本质
标线随配置自动生成✅ 取手画标线是 CS1 造景玩家最大的时间黑洞
左/中/右对齐（3→4 车道从一侧加）✅ 取我们的 offset_dm 天然支持
车道级连接件（第 1 道接第 3 道）❌ 不取§3.6.5b 已定不做；我们靠 OD 聚合，不需要

⚠ 一句话：CSUR 的自由度是"道级连接"，我们要的是"断面自由"。 两者在"横截面能随便配"这一层重合，但连接层完全不同。别照搬它的模块系统，那是另一个子系统。

3.10.13 part 的数据表达（B2 实现时看）

band {
  parts: [                       # 从左到右有序
    { kind: sidewalk,   width_dm: 30 },
    { kind: bike,       width_dm: 25, isolation: marking },
    { kind: lane_group, count: 2, lane_w_dm: 35, lane_type: normal, arrows: [left, straight] },
    { kind: median,     width_dm: 30, green: true },
    { kind: lane_group, count: 2, lane_w_dm: 35, lane_type: normal, arrows: [straight, right] },
    { kind: bike,       width_dm: 25, isolation: marking },
    { kind: sidewalk,   width_dm: 30 }

}
规则说明
parts 从左到右有序不存 x 坐标，只存宽度序列（推导位置，避免不一致）
总宽 = Σwidth_dm自动校验；不合法时吸附到最近合法值
lane_group 是唯一承载车流的部分其余 part 不参与通行能力计算

⚠ part 序列是"形状数据"，属 R34 的「绝不能浅」清单（改形状要重写下游）。 所以 B2 只实现 local 用到的那几种 part（人行道 / lane_group / 标线中心线）， 但数据结构要能容纳全部 part 种类。

3.10.15 对齐：左 / 中 / 右（3 车道扩 4 车道为什么需要它）

问题（CS1 的真实缺陷）：3 车道接 4 车道时，CS1 是居中对接， 结果是两边各多出半条道的错位。现实中是从一侧加一条，另一侧边线不动。

我们的解：band.align 三值 + offset_dm。

align行为用在哪
center两侧对称扩双向路（默认）
left左边线固定，右侧加宽靠中央分隔一侧对齐（如匝道分流）
right右边线固定，左侧加宽最常见：车道数增加时从内侧加
manual直接给 offset_dmexpress_split 两单行道间距变化

⚠ 这条几乎不花代价（我们已经存了 offset_dm），但视觉收益极大： 玩家会觉得"这路是设计过的"，而不是"两条管子插在一起"。 ⚠ 验收：RD-C7（见 §3.10.9）——3 车道接 4 车道，两侧边线必须连续（误差 ≤5 cm）。
